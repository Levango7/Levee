# ADR-003: 凭据本地 AES-GCM 加密存储

| 字段 | 内容 |
|------|------|
| 编号 | ADR-003 |
| 标题 | 凭据本地 AES-GCM 加密存储（MVP 阶段不依赖外部 KMS） |
| 状态 | 已采纳 |
| 日期 | 2026-08-16 |

## 上下文

LEVEE 需要存储目标机连接凭据（SSH 密码/密钥、WinRM 密码、API token），这些凭据是变更执行的基础。凭据管理面临以下约束：

- 凭据不能以明文形式落盘（安全红线）
- 凭据不能出现在审计 trace 和日志中（防泄露）
- MVP 阶段不依赖外部 KMS（Vault / CyberArk），保持单二进制零依赖部署
- V1 阶段需要对接外部凭据代理（Vault / CyberArk）

可选方案：

1. **本地 AES-GCM 加密 + argon2 密钥派生**：凭据加密后存入 SQLite，主密码由环境变量注入
2. **外部 KMS（Vault / CyberArk）**：凭据存储在外部 KMS，按需获取，但引入外部依赖
3. **操作系统密钥环（keyring）**：利用 OS 原生密钥管理，但跨平台兼容性差
4. **明文存储 + 文件权限保护**：最简单，但不满足安全要求

## 决策

选择 **本地 AES-GCM 加密 + argon2 密钥派生** 作为 MVP 凭据存储方案。

加密流程：

1. 用户通过 `LEVEE_MASTER_PASSWORD` 环境变量提供主密码
2. 使用 argon2id 从主密码派生 256 位加密密钥（加盐，防彩虹表）
3. 使用 AES-256-GCM 加密凭据明文（提供机密性 + 完整性 + 认证）
4. 加密密文 + salt + nonce 存入 SQLite credentials 表
5. apply 时按目标机按需解密获取凭据，用完即弃（内存中不缓存明文）

关键设计要点：

1. **凭据不落盘明文**：SQLite 中只存加密密文，即使数据库文件被复制也无法获取明文
2. **凭据不进 trace / 日志**：审计 trace 和日志中只记录凭据 ID，不记录明文或密文
3. **按需获取**：apply 时才解密凭据，用完即从内存清除，减少明文暴露窗口
4. **主密码环境变量**：主密码通过环境变量注入，不写入配置文件，不落盘
5. **argon2id 派生**：防暴力破解，argon2id 是 OWASP 推荐的密码哈希算法

## 后果

### 正面

- 满足 MVP 单二进制零依赖部署约束，无需外部 KMS
- AES-GCM 提供认证加密，防篡改 + 防重放
- argon2id 密钥派生抗暴力破解，主密码安全性有保障
- 凭据不进 trace / 日志，审计链路无泄露风险
- V1 对接外部 KMS 时，CredentialStore 接口层隔离，仅需新增 KMS 实现

### 负面

- 主密码丢失则所有凭据不可恢复（无主密码恢复机制）
- 主密码通过环境变量传递，进程环境可见（/proc/pid/environ）
- 单机存储，不支持凭据跨节点同步（集群形态需外部 KMS）
- argon2 计算开销较高（约 100ms/次），批量解密时需注意性能

### 缓解

- 文档明确提示用户妥善保管主密码，丢失不可恢复
- V1 引入 Vault / CyberArk 凭据代理，主密码仅用于本地加密凭据的降级场景
- 批量解密时复用派生密钥（argon2 结果缓存至 apply 结束），避免重复计算
- 主密码可通过 systemd EnvironmentFile / Kubernetes Secret 等机制安全注入
