# ADR-001: 选择 SQLite 作为 MVP 存储引擎

| 字段 | 内容 |
|------|------|
| 编号 | ADR-001 |
| 标题 | 选择 SQLite 作为 MVP 存储引擎 |
| 状态 | 已采纳 |
| 日期 | 2026-08-16 |

## 上下文

LEVEE 需要持久化存储以下数据：

- 变更 run 状态与批次执行记录
- 审计 trace 与哈希链
- 凭据加密密文
- 互斥锁状态
- 审批记录与权限矩阵
- 模板与配置

MVP 阶段的核心约束是"单二进制零依赖部署"（设计红线 D12.1）：空机器下载二进制 + 配置文件即可启动，无需安装外部数据库或运行时。

可选方案：

1. **SQLite（纯 Go 实现，modernc.org/sqlite）**：嵌入式数据库，零 CGO 依赖，单文件存储，WAL 模式支持并发读写
2. **PostgreSQL**：生产级关系数据库，高并发、高可用，但需独立部署与运维
3. **BadgerDB / BoltDB**：嵌入式 KV 存储，无需 SQL，但缺乏关系查询能力
4. **文件系统 + JSON**：最简单，但无事务、无并发控制、无查询能力

## 决策

选择 **SQLite（modernc.org/sqlite，纯 Go 零 CGO 实现）** 作为 MVP 存储引擎。

关键选型理由：

1. **单二进制零依赖**：modernc.org/sqlite 是纯 Go 翻译的 SQLite，无需 CGO，交叉编译无障碍，满足 MVP 部署约束
2. **嵌入式零运维**：SQLite 以单文件形式嵌入进程，无需独立部署数据库实例，降低 MVP 交付复杂度
3. **SQL 能力**：支持完整 SQL 语法，便于表达 run / batch / step / trace 之间的关联查询
4. **WAL 模式**：开启 WAL 后读写可并发，MVP 批量 100 台目标机的 trace 写入场景可满足
5. **WORM 模拟**：SQLite 追加只写 + 校验和可模拟 WORM 审计存储，满足审计不可篡改要求
6. **V1 迁移路径清晰**：V1 阶段引入 PostgreSQL 时，Store 接口层隔离，仅需替换实现，上层代码无感

## 后果

### 正面

- MVP 交付物为单二进制，空机器一键跑通，满足 G-02 门禁
- 无外部数据库依赖，CI/CD 流水线简单，测试环境搭建零成本
- 纯 Go 实现避免 CGO 编译复杂性，跨平台构建（linux/windows/darwin）无障碍
- Store 接口层解耦，V1 迁移 PostgreSQL 仅需替换实现层

### 负面

- SQLite 写并发上限（WAL 模式下单写锁），万级目标机场景可能成为瓶颈（MVP 明确不做万级）
- 不支持集群形态（多实例共享存储），V1 集群形态必须迁移至 PostgreSQL
- 无内置主从复制，数据备份需依赖文件系统级备份
- modernc.org/sqlite 比 CGO 版本性能略低（约 10-20%），MVP 场景可接受

### 缓解

- T043 trace 写入采用批量提交 + 单写锁策略，减少写锁争用
- T089 压测验证 100 台目标机场景下 SQLite 性能达标
- Store 接口层严格解耦，V1 迁移 PostgreSQL 时仅需替换 SQLite 实现为 PostgreSQL 实现
