# ADR-007: 批次控制器并发限速设计

| 字段 | 内容 |
|------|------|
| 编号 | ADR-007 |
| 标题 | 批次控制器并发限速设计（三级限速 + 排队 + 超时） |
| 状态 | 已采纳 |
| 日期 | 2026-08-16 |

## 上下文

LEVEE 的批次执行模型是"批间串行 + 批内并发"：批次之间按顺序执行（批间等待可配），批次内目标机并发执行。并发控制需要解决以下问题：

- 大规模并发可能压垮目标机（SSH 连接风暴 / WinRM 请求洪峰）
- 不同通道类型的并发能力不同（SSH 支持多路复用，WinRM 单连接单命令）
- 同一目标机不应被多个 step 并发执行（状态竞争）
- 限速不应导致任务丢失（背压排队而非拒绝）

可选方案：

1. **无限制并发**：批内所有目标机同时执行，简单但可能压垮目标机
2. **固定并发池**：全局固定并发上限，简单但不区分通道和目标机
3. **三级限速 + 排队 + 超时**：全局 + 单通道 + 单目标机三级限速，超限排队，排队超时失败
4. **自适应限速**：根据目标机响应时间动态调整并发，复杂度高

## 决策

采用 **三级限速 + 排队 + 超时** 方案。

三级限速定义：

| 级别 | 维度 | 默认值 | 配置项 | 说明 |
|------|------|--------|--------|------|
| L1 | 全局并发 | 100 | `channel.max_concurrent` | 所有通道总并发连接上限 |
| L2 | 单通道并发 | 按通道类型 | `channel.ssh.max_concurrent` / `channel.winrm.max_concurrent` | 单通道类型并发上限 |
| L3 | 单目标机并发 | 1 | `channel.max_per_host` | 同一目标机最大并发连接数 |

限速执行流程：

1. 批次控制器提交执行任务到限速调度器
2. 调度器检查 L1（全局并发）：未超限则进入 L2 检查，超限则排队
3. 调度器检查 L2（单通道并发）：未超限则进入 L3 检查，超限则排队
4. 调度器检查 L3（单目标机并发）：未超限则执行，超限则排队
5. 排队任务按 FIFO 顺序等待，有执行槽位释放时自动调度
6. 排队超时（默认 5min）则任务以 `retryable` 失败语义失败，计入审计 trace

背压机制：

- 当连接池满或目标机响应超阈值，新任务排队而非拒绝
- 排队超时按 R7 产出结构化失败（包含排队时长 / 等待位置 / 超时原因）
- 背压状态通过 `levee status` 可观测（当前排队数 / 活跃连接数 / 限速配置）

## 后果

### 正面

- 三级限速覆盖全局 / 通道 / 目标机三个维度，防止连接风暴压垮目标机
- L3 单目标机并发 = 1 避免同一主机的状态竞争，保证执行语义正确
- 背压排队而非拒绝，任务不会因限速而丢失
- 排队超时产出结构化失败，满足 R7 红线（失败可定位）
- 限速参数可配置，不同环境可按需调整

### 负面

- 三级限速增加调度器复杂度，需维护三级计数器和排队队列
- L3 单目标机并发 = 1 在多 step 并发场景下可能成为瓶颈（如同一主机的 file + svc 步骤需串行）
- 排队超时默认 5min 可能在网络恢复慢的场景下不够
- 限速配置不当（如 L1 过低）可能人为造成排队瓶颈

### 缓解

- L3 单目标机并发可配置，多 step 场景可调整为 2-3（需用户确认步骤间无状态竞争）
- 排队超时可通过 `channel.queue_timeout` 配置调整
- `levee status` 提供限速状态可观测性，帮助运维调优限速参数
- 批量 100 台场景压测验证限速配置合理性，确保端到端耗时 <= 10min
