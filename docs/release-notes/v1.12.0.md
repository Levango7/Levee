# v1.12.0 Release Notes

**Release Date**: 2026-08-27

## Overview

This release focuses on self-observability and operational tooling: a
Prometheus-compatible metrics endpoint, data backup/restore commands,
OpenTelemetry tracing, dependency-update automation (Dependabot), CodeQL
security analysis, a complete configuration example, and a Code of Conduct.

## New Features

### 1. Self-metrics endpoint (`internal/metrics/`)

- Lightweight atomic-counter metrics collector (no external runtime cost)
- Prometheus text exposition format 0.0.4
- 10 metric families: change lifecycle states, batch duration, gates,
  approvals, channel acquisition, locks, rollbacks, backups, alerts, etc.
- Mounted at `/metrics` on the REST gateway (`levee serve`)
- Coverage 98.1%, 19 tests

### 2. Data backup/restore (`internal/backup/` + `cmd/levee/cmd_backup.go`)

- New CLI commands:
  - `levee backup [--output <path>] [--verify-only] [--pg-dsn <dsn>]`
  - `levee restore --input <path> [--yes]`
- SQLite: `VACUUM INTO` snapshot + `integrity_check` + `.sha256` checksum
- PostgreSQL: pure-Go SQL dump via pgx (no `pg_dump` binary dependency)
- Restore safety chain: automatic `.pre-restore` safety backup before
  replacement, atomic file replacement, stale-WAL cleanup afterwards
- Coverage 86.8%, 60 tests

### 3. Dependabot (`.github/dependabot.yml`)

- Scheduled dependency update workflow for three ecosystems:
  gomod / github-actions / docker

### 4. CodeQL (`.github/workflows/codeql.yml`)

- CodeQL security analysis on push, pull request, and a weekly schedule

### 5. `config.example.yaml`

- Complete example covering all 52 config keys
- Cross-checked one-by-one against `internal/config/config.go`
  (zero fabricated keys)
- Each key documented with default value and scenario examples

### 6. `CODE_OF_CONDUCT.md`

- Contributor Covenant 2.1 full text

### 7. OpenTelemetry tracing (`internal/tracing/`)

- `Tracer` interface + stdouttrace exporter
- W3C `traceparent` parse/format utilities for cross-service context
  propagation
- Initialized on `serve` startup; initialization failure degrades to a noop
  tracer and never blocks startup
- New `tracing` config section: `enabled` / `exporter` / `endpoint`
  (disabled by default)
- Built on OTel v1.44.0; coverage 95.3%, 17 tests

## Architecture Note

- `internal/grpc/rest.go`: added a `SetExtraRoute` generic extension point
  (~30 lines) so external HTTP handlers can be mounted on the gateway mux
  (previously there was no external injection point). Used for `/metrics`
  in this release. No impact on existing gateway behavior.

## Upgrade Notes

- **Tracing is disabled by default** (`tracing.enabled: false`). No migration
  is required; opt in by setting `tracing.enabled: true` and choosing an
  exporter (`stdout` or OTLP endpoint).
- **`levee backup` / `levee restore` are new commands** and can be used
  directly; no configuration change is required for SQLite deployments.
  PostgreSQL backups accept the target DSN via `--pg-dsn`.
- No breaking changes to existing config keys, CLI commands, or APIs.
