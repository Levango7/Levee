## Highlights

LEVEE v1.4.0 是 **Phase 3 — 生态扩展** 里程碑版本。在 v1.3.0 平台化（Web UI、插件系统、RBAC、ChatOps）的基础上，v1.4.0 将 LEVEE 从单节点平台扩展为**分布式、多租户、可巡检、移动可达**的变更管理生态：

- **F04 分布式执行** — Agent 常驻进程 + 多节点调度器（任务分片 + 负载均衡），突破单节点性能上限
- **F07 多租户** — 租户隔离（行级数据隔离 + 命名空间）+ 资源配额 + 审计隔离，支持多团队共享同一集群
- **F10 配置漂移检测增强** — 定期巡检调度（cron）+ 漂移基线自动生成 + 漂移告警 + 趋势报告
- **F12 移动端审批** — APNs/FCM 推送通知 + 深度链接 + 一键审批/驳回 + 响应式 Web UI 适配

至此，LEVEE MVP+ Roadmap 中 F01–F14 全部特性已交付，F15 集群形态（PostgreSQL store + 分布式锁）作为基础设施支撑也已就位。

## New Features

### F04: 分布式执行

Agent 常驻进程架构，master 节点调度任务到多台 Agent 执行，突破单节点性能上限。

**核心组件**:

| 组件 | 包 | 职责 |
|------|-----|------|
| Agent | `internal/agent` | 常驻进程、心跳、注册/注销、任务执行、结果回传 |
| Scheduler | `internal/scheduler` | 多节点调度器、任务分片、负载均衡 |

**负载均衡策略**:

| 策略 | 说明 |
|------|------|
| `round-robin` | 轮询调度，均匀分配任务 |
| `least-loaded` | 最少负载优先，按当前执行任务数选择 |
| `capability-aware` | 能力感知，按 Agent 声明的 `caps` 匹配任务类型 |

**CLI 命令**:
```bash
# 启动 Agent 常驻进程
levee agent start --addr :9091 --master localhost:9090 --caps shell,file,pkg

# 查看 Agent 状态
levee agent status

# 列出所有已注册 Agent（master 端）
levee agent list

# 查看 Agent 详情
levee agent show <agent-id>

# 移除 Agent
levee agent remove <agent-id>
```

**典型部署**:
```bash
# 终端 1: 启动 master
levee serve --addr :9090

# 终端 2-4: 启动多个 Agent
levee agent start --addr :9091 --master localhost:9090 --caps shell,file
levee agent start --addr :9092 --master localhost:9090 --caps shell,pkg
levee agent start --addr :9093 --master localhost:9090 --caps shell,file,svc
```

### F07: 多租户

租户隔离与资源配额，支持多团队共享同一 LEVEE 集群，互不干扰。

**核心组件**:

| 组件 | 包 | 职责 |
|------|-----|------|
| Tenant Model | `internal/tenant` | 租户模型、状态机（active/suspended） |
| Resource Quota | `internal/tenant` | 资源配额（目标机数/并发数/存储空间） |
| Data Isolation | `internal/tenant` | 行级数据隔离、命名空间 |
| Tenant Manager | `internal/tenant` | 租户管理器、CRUD、配额校验 |

**隔离维度**:
- **行级数据隔离**: 所有数据表附带 `tenant_id` 列，查询自动注入租户过滤
- **命名空间隔离**: 模板、目标机、凭据等资源按租户命名空间隔离
- **审计隔离**: 审计 trace 按租户分片，租户间不可见
- **资源配额**: 目标机数、并发变更数、存储空间三维度配额限制

**CLI 命令**:
```bash
# 创建租户
levee tenant create --name acme --display "ACME Corp" \
  --max-targets 100 --max-changes 10

# 列出 / 查看 / 暂停 / 恢复 / 删除
levee tenant list
levee tenant show <tenant-id>
levee tenant suspend <tenant-id> --reason "合规审查"
levee tenant resume <tenant-id>
levee tenant delete <tenant-id>

# 配额管理
levee tenant quota <tenant-id> --max-targets 200 --max-changes 20

# 使用量查询
levee tenant usage <tenant-id>
```

### F10: 配置漂移检测增强

在 v1.0.0 基础漂移检测之上，增加定期巡检调度、基线自动生成、漂移告警与趋势报告。

**核心组件**:

| 组件 | 包 | 职责 |
|------|-----|------|
| Drift Engine | `internal/drift` | 漂移检测引擎、对比算法 |
| Baseline Manager | `internal/drift` | 基线管理、自动生成、版本化 |
| Schedule Manager | `internal/drift` | 定期巡检调度（cron） |
| Report Analyzer | `internal/drift` | 报告生成、趋势分析 |

**新增能力**:
- **基线自动生成**: 从最近一次 apply 的预期状态自动生成基线，无需手动维护
- **定期巡检**: cron 表达式调度，支持每日/每周/自定义周期
- **漂移告警**: 检测到漂移时自动触发告警通知
- **趋势报告**: 按时间维度统计漂移次数、分布与趋势

**CLI 命令**:
```bash
# 自动生成基线
levee drift baseline auto --host web-01

# 手动设置基线
levee drift baseline set --host web-01 --file baseline.json --name "v1.0 基线"

# 列出基线
levee drift baseline list --host web-01

# 检测漂移
levee drift detect --host web-01 --baseline auto

# 定期巡检调度
levee drift schedule add --name daily-check --cron "0 2 * * *" --hosts web-01,web-02
levee drift schedule list
levee drift schedule remove <schedule-id>
levee drift schedule run <schedule-id>

# 漂移报告
levee drift report --host web-01 --days 30
```

### F12: 移动端审批

APNs / FCM 双平台推送通知 + 深度链接 + 一键审批/驳回 + 响应式 Web UI 适配，让审批人随时随地处理变更。

**核心组件**:

| 组件 | 包 | 职责 |
|------|-----|------|
| APNs Client | `internal/push` | APNs HTTP/2 + ES256 JWT 认证 |
| FCM Client | `internal/push` | FCM HTTP v1 + OAuth2 认证 |
| Push Manager | `internal/push` | 设备管理、推送路由、重试 |
| Deep Link | `internal/push` | 深度链接生成与解析 |
| Mobile Approval | `internal/approval/mobile` | MobileApprovalService |
| Responsive UI | `web/` | `MobileApprovalView.vue` + `useResponsive.ts` |

**推送协议**:
- **iOS**: APNs HTTP/2 API + ES256 JWT（基于 p8 私钥）
- **Android**: FCM HTTP v1 API + OAuth2（基于服务账号 JSON）

**深度链接**:
- 格式: `levee://approval/<run-id>`
- 点击通知直接跳转到移动端审批页面
- 一键审批/驳回，无需打开浏览器

**CLI 命令**:
```bash
# 配置 APNs
levee push config --platform ios --key AuthKey.p8 --key-id ABC123 --team-id TEAM456

# 配置 FCM
levee push config --platform android --project my-project --service-account sa.json

# 注册 / 注销设备
levee push register --user alice --token <device-token> --platform ios
levee push unregister --user alice --token <device-token>

# 发送推送
levee push send --user alice --title "审批请求" \
  --body "变更 run-123 待审批" \
  --deep-link "levee://approval/run-123"

# 设备管理 / 测试 / 配置查看
levee push devices --user alice
levee push test --user alice
levee push config
```

**Web UI 响应式适配**:
- `MobileApprovalView.vue`: 移动端审批专用视图，大按钮、单列布局
- `useResponsive.ts`: 响应式断点 composable，自动检测设备类型并切换布局

## Installation

### 从源码构建

```bash
# 克隆仓库
git clone https://github.com/levee/levee.git
cd levee
git checkout v1.4.0

# 构建 CLI
go build -o levee ./cmd/levee

# 构建 Web UI 前端（可选，已预编译嵌入）
cd web && npm install && npm run build && cd ..

# 验证
./levee system version
```

### 快速开始

```bash
# 1. 初始化配置
levee system config set db.path ./levee.db
levee system config set server.grpc.port 9090

# 2. 添加目标机
levee target import --file targets.yaml

# 3. 创建变更
levee new --template deploy-web --params env=staging,version=v2.1.0

# 4. 启动 gRPC 服务端（终端 1）
levee serve --addr :9090

# 5. 启动 Web UI（终端 2）
levee web --addr :8080 --grpc-addr localhost:9090

# 6. 通过浏览器访问 http://localhost:8080
```

### 分布式部署快速开始

```bash
# 1. 启动 master 节点
levee serve --addr :9090

# 2. 在多台机器启动 Agent
levee agent start --addr :9091 --master master.host:9090 --caps shell,file,pkg

# 3. 创建租户（可选）
levee tenant create --name acme --display "ACME Corp" --max-targets 100

# 4. 配置移动端审批（可选）
levee push config --platform ios --key AuthKey.p8 --key-id ABC123 --team-id TEAM456
```

## Security

### 已修复（v1.0.1）

| ID | 严重度 | 问题 | 修复 |
|----|--------|------|------|
| SA-001 | CRITICAL | 凭据明文日志泄露 | 凭据字段全局 redaction |
| SA-002 | CRITICAL | SSH 私钥内存未清零 | SecureZero 调用 |
| SA-003 | CRITICAL | argon2 参数低于 OWASP 建议 | 提升至 194MiB / t=3 |
| SA-004 | HIGH | WinRM 密码环境变量泄露 | 从 env 读取后立即清除 |
| SA-005 | HIGH | Plan hash 未包含审批人 | hash 输入增加 approver |
| SA-006 | HIGH | 回滚未触发独立通知 | 回滚通知路径独立 |
| SA-007 | HIGH | 哈希链校验未校验根哈希 | 增加根哈希锚定 |
| SA-008 | HIGH | 互斥锁抢占未检查状态 | 抢占前状态检查 |

### 安全特性

- 凭据 AES-GCM 加密存储 + argon2id 密钥派生（194MiB / t=3）
- WORM 审计存储 + 哈希链校验，篡改可检出
- 三级审批模型，高危变更强制人工审批
- gRPC TLS + Bearer token 认证
- 插件子进程沙箱隔离，资源限制 + 崩溃恢复
- RBAC + ABAC 多维权限策略
- **租户隔离**: 行级数据隔离 + 命名空间 + 审计分片（v1.4.0 新增）
- **APNs JWT 短期令牌**: ES256 JWT 有效期 30 分钟，自动轮换（v1.4.0 新增）
- **FCM OAuth2 token**: 服务账号 token 自动获取与缓存（v1.4.0 新增）

## Known Limitations

1. **Agent 心跳超时**: Agent 心跳超时默认 45s（3 倍心跳间隔），超时后 master 标记 Agent 为 `lost`，需手动 `agent remove` 清理。
2. **租户删除**: 租户删除需先 `suspend` 且无活跃变更，`--force` 删除将级联清理租户所有数据，操作不可逆。
3. **漂移基线存储**: 基线存储在 SQLite 中，大量基线可能影响查询性能，建议定期清理过期基线。
4. **APNs token 轮换**: APNs JWT token 缓存 30 分钟，master 重启后重新生成。
5. **FCM 服务账号**: 服务账号 JSON 文件需妥善保管，泄露后可发送任意推送。
6. **移动端 Web UI**: 响应式适配针对审批场景优化，完整管理功能仍建议使用桌面端。
7. **Web UI 预编译**: 前端构建产物已嵌入二进制，修改前端需重新 `npm run build` + `go build`。
8. **ChatOps 回调**: 需要公网可达的回调地址，建议通过反向代理暴露。
