## Behaviour changes (read first)

1. **匿名 `levee approve` / `levee reject` 现在被拒（breaking）**。CLI 与 ChatOps 的投票改走 serve 的同一条路（`ChangeService.ApproveChange`/`RejectChange`），主体必须是已验证身份：本地命令要给 `--as`，否则报错与远程调用方看到的逐字相同（"a shared --token authenticates the deployment, not a person"）。依赖匿名投票的脚本必须在升级前改。附带两个变化：结算与审计由服务完成（服务级 audit 行第一次有 CLI 投票）；`--level` 变成预检（服务自己选第一条 pending approval，不认档位）。
2. **装了并「启用」的插件现在真的会被执行**。`notify` 型插件在 boot 时装配进通知管理器（与 webhook 平权），`gate` 型插件在 plan 期参与可执行性判定。**默认零变化**：注册表为空或不启用即未配置态；但一旦启用，boot 时二进制消失会**拒绝启动**并点名（逃生门 `levee plugin disable`）。
3. **清单的 env 归属有事实源了**。`target-ownership.yaml` 存在时，registry 胜过 `labels["env"]`；未登记的主机回落 labels；文件加载失败**拒绝启动**。重新导入不再能把已登记的 prod 主机改标成 dev——这类改写需要原 env 的 admin，且预览与写入同一套规则。
4. **告警按归属判可见性**。告警的读与订阅改为按**告警自己所属的环境**要 `view`，流按可见环境**收窄**而不是整条拒绝；配置了 `alert-sources.yaml` 后，未登记 / 错凭据 / 无凭据的入站告警一律 `Unauthenticated` 且不落 ring。例外表已清空（棘轮 1→0）。
5. **审批超时第一次真的会发生**。`approval.CheckExpiry` 接进 serve 的清扫器，三层超时（4h/8h/24h）第一次有消费方，pending 到期落成 `expired`。**同批还让 run 终态进聊天**：`running` / `completed` / 失败与各类回滚终态各播一张卡（部分回滚不得读作干净失败），中间跳（paused / pending_approval）刻意不播。LEVEELang 的 `gate_approver` 审批记录刻意不带过期时间，清扫跳过。
6. **`probe` 门禁的 `{target}` 现在会展开**（`mode: remote` + `kind: http`）。此前按文档写的 URL 永远过不了——如果你的门禁一直是红的而文档说应该过，这是原因。
7. **`assignments.result` 收窄**：非终态的 run 状态不再透传进结果列（该列词表由 `state.AssignResult*` 冻结）。查历史结果时不会再看到中途状态冒充终态。
8. **构建要求 Go 1.26.10**（`go` 指令上移，收口 GO-2026-6809）。**前端开发工具链** vitest 3→5、vite 5→7。

## Security

- **GO-2026-6809**（标准库，Distrust compromised intermediate）由 `go` 指令 1.26.9 → 1.26.10 收口；该公告曾让与本主题无关的 PR 的 `govulncheck` 变红。
- **前端生产依赖 4 个 high 清零**：axios（原型污染/头注入/ReDoS/重定向 SSRF，控制台全部 HTTP 走它）、`@vue/server-renderer` XSS、brace-expansion、source-map-js；剩余 5 条 dev-only 由 vitest 3→5 收口。
- **ChatOps 入向重放**：钉钉/飞书的 `sign` 只覆盖时间戳、body 不参与签名，此前在新鲜度窗口内可换 body 重放；现按 `(ts, sign)` 单次有效。
- **CLI/ChatOps 投票**：身份进入服务层，quorum 由服务端强制（不再靠调用方自觉）；`DecisionGuard` 补上 gate 投票与移动深链两条绕行路径。
- **告警**：每源入口身份 + 按归属判可见性，例外表清空。
