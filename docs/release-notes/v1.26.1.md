## Overview

本版是一次**契约与诚实性收口**：把四条「对外说一套、实际另一套」的路径改成单一事实源，并把
「写得出来」与「跑得起来」之间的最后一程补齐（裸机取证脚本化）。按主题分（10 个小节，另加依赖升级）：

1. **契约收口（4 节）**——① 审计链校验原先有两个口径：`/audit/traces` 自带一份校验、`/audit/verify`
   另一份，「这条链完好吗」取决于你问哪个端点；现在 `trace` 端点改用 `/audit/verify` 的**同一个校验器**，
   链校验**只有一个口径**，并把 keyed/unkeyed 的口径差异显式暴露（弱保证不再被说成强保证）。
   ② `plan`/`apply` 的拒绝分类：请求本身不成立答 **400**、状态不允许答 **412**，不再一律 500
   （500 会让调用方重试，而重试一个「语法错」的请求永远错）。
   ③ SQL 审核对 DDL 的**半读**问题：只被解析器读到一半时，前缀曾被当作整条语句打分；现在读不了时
   点明**方言/解析器读不到**，而不是拿半个语句下结论。④ `pg.query` 的 SQL **从未被审核**——
   三处收集器只认 `mysql`，走 `pg.query` 的数据库变更此前完全绕过 SQL 审核链（这是本版唯一一处
   「治理承诺有洞」的修复）。
2. **实时面（1 节）**——SSE 此前用 `EventSource`，而 `EventSource` **无法带 Authorization 头**，
   于是控制台的实时面板在真实（开了鉴权的）服务端下**是死的**；改为 `fetch` + Bearer，
   并按**事件名**分派具名帧（此前同名事件挤在一个通道里靠 body 自行分辨）。
3. **新增能力（3 节）**——① 信创裸机取证**脚本化**（一次命令拿全部证据；实跑修掉三个真 bug：
   漏 plan 步骤、就绪探针未带 token、凭据库缺主口令）。② **静态影响面**：这条变更动到哪些表、
   什么操作、有没有整表扫描——审批人不必读 SQL 才知道影响面。③ **LE108**：声明了 `irreversible: true`
   却没声明任何补偿的步骤，编译期点名（warning，不阻断——有些变更真的不可逆）。
4. **前端回归守卫（1 节）**——发布单白屏（`r.ticket` 解包一个服务端从不发送的信封）变成**可测**的：
   用服务端真实形状驱动客户端并断言七分段可达；顺带修掉两个遗漏（对话框写死宽度、CSV 导入按钮无
   防重入），并把这两类缺陷做成机器守卫。**变异实测三类守卫都承重。**
5. **发布与门禁（1 节）**——发布说明的实况不得漂移：新门禁把每份 release notes 与真实 tag 对账
   （tag 对象、指向的提交），历史 17 版零漂移。

## 升级必读（契约与行为变更）

### 会改变客户端行为的四处

- **SSE 现在要求鉴权**：`/changes/:id/events`（与 `/alerts/stream`）从 `EventSource` 改为
  `fetch` + Bearer。**自己写的 SSE 客户端必须带 token**，否则拿到 401。控制台已随之更新。
  在此之前，开了鉴权的服务端上 EventSource 根本连不上——控制台的实时面板是死的。
- **`plan`/`apply` 的错误码分类**：请求不成立从 500 改为 **400**（parameter/argument），
  状态不允许从 500 改为 **412**（precondition）。按 500 判「重试」的客户端会不再重试
  （这正是目的），但按 `code == 500` 做兜底的分支要复核。
- **审计链校验口径统一**：`/audit/traces` 不再自带一份校验，改用 `/audit/verify` 的同一校验器。
  **同一个变更在两个端点现在给同一个答案**；此前靠 `trace` 端点读链判定、又与 `verify`
  结论不一致的客户端会看到变化（以 `verify` 为准）。
- **keyed/unkeyed 显式区分**：未设 `LEVEE_AUDIT_HMAC_KEY` 时审计链用的是无密钥 SHA-256，
  校验结果现在**如实标注**（弱保证不再被呈现为强保证）。此前它能验「链没断」，但**不能**
  抗重算攻击——生产部署应设 key。

## 诚实边界（本版**没有**做到的事）

- **D-5「DDL 自动回滚」仍未落地**：变更前 schema 快照取证仍在并行在途（PR #405，**未进本版**）。
  没有正确逆向（`DROP COLUMN` 的逆需要列定义，语句文本里没有）之前，**不生成** undo 动作——
  顺序必须是先快照再生成。LE108 现在会**点名**这类缺口，但缺口本身未填。
- **两条 P1 仍未复现**：`internal/calendar` 在 windows-latest 上的偶发访问违例、
  `browser-check` 在 windows-latest 上的偶发失败。两者都有每日自动复现探针在盯
  （复发即留证据），但**探针不等于修复**，台账状态仍为 open。
- **信创裸机仍未验证**：本版把取证脚本化了（在本机 Linux amd64 自指口径完整跑通两次：
  `v1→v2→v1`、`audit/verify valid=true`），但矩阵里「麒麟/统信 × amd64（裸机）」那格**仍未改状态**，
  要等真机上跑一遍 `summary.txt` 三行都对上。
- **`dialogs` 守卫只防溢出、不防难读**：它保证对话框宽度不超出视口，不保证内容在窄屏下可读——
  后者需要真浏览器复核（`browser-check` 的窄屏档仍是已登记缺口）。
