## Behaviour changes (read first)

1. **`priority` 现在在入口校验，非法值被拒**（PR #132）。`CreateChange` 与 `InstantiateTemplate` 只接受
   `low|normal|high|urgent`，其余返回 `InvalidArgument` 并列出允许值；空值按 `normal` 落库。
   **这是行为变更**：此前任何串都被静默存下。若调用方曾传 `medium`（那是 impact 尺度的词、
   不是优先级词），现在会开始收到错误。
2. **schema v9：`runs.priority` 成为独立列**，`approval_level` 回到只装档位（`standard|high|emergency`）。
   迁移随启动自动执行（SQLite 与 PostgreSQL 两架梯子各加一步，无需人工）。回填**只搬可判定的值**
   （`low/normal/urgent`），**`high` 刻意留在原列**——它是两套词共享的拼写，搬过去等于替引擎猜它
   当初的意思。因此：历史行的 `priority` 是空串，控制台显示「未记录」（空白会被读成「这个变更
   没主张任何紧迫度」，而数据里得不到这个断言）；`approval_level` 里仍可能出现优先级词，那是
   v9 之前的事实，不是脏数据。`approval_level` 未被清空，历史行的自动审批行为逐字节不变。
3. **自动审批的一条偶然通道消失**（同上）。拆列之前，客户端送 `priority: high` 会因为在档位列里被
   读成「high 档」而**意外**触发自动审批拒绝；拆列之后这条偶然通道不存在了，门禁只看派生档位。
   **这不是放宽**：规范 §8.1 的 `auto_approve` 约束写在 approval 块的 `level` 上，而含不可逆步骤的
   计划其 floor 至少 `high` ⇒ 仍被拒。
4. **8 个写 RPC 开始按权限矩阵判定**（PR #112）。`CreateChange`/`CloneChange` 取 `plan`，
   `RetryChange`/`RetryHost` 取 `apply`，`CancelChange`/`PauseChange`/`ResumeChange` 各取同名动作，
   `ArchiveChange` 取 `admin`（归档会连带 `purge_artifacts` 删证据，挂 `cancel` 等于让所有能停
   「运行中」变更的人获得清「已完成」变更证据的权限）。**未配 `permissions.yaml` 的部署行为一字不变**；
   配了矩阵的部署里，此前任何已认证调用方都能对**任意环境**创建/克隆/重试/取消/暂停/归档，现在会被拒。
   `CloneChange` 判的是**新变更落地的环境**（有 override 用 override）——只判源环境会让「能在 dev 计划」
   的人把 prod 变更克隆进 prod。拒绝先于一切副作用，并按 SA-007 落 `permission.denied` 审计行。
5. **重试上限由服务端强制**（PR #106）。`docs/levee-api.md` 承诺的「重试次数有上限（默认 3），
   超限升级人工」此前只是 CLI 的私有逻辑，`RetryChange`/`RetryHost` 完全不检查 ⇒ 经控制台/API 可无限重试。
   现在两个 RPC 在**执行之前**按同一份预算（`internal/retrybudget`）判定，超限返回
   `ResourceExhausted`（REST **429**）。`RetryHost` 任一主机超限即整批拒绝并点名是哪几台。
   同批修掉一个此前查不到的计数缺陷：每主机计数原先「先 `Limit=4` 拉最近 4 行、再在 Go 里按 Target
   过滤」，主机交错重试时目标主机的行会被挤出窗口（实测读 0 而非 3），现改为 SQL 层过滤。
6. **审计行的形状变了**，下游按旧形状解析的人要改（PR #105 / #107）。`retry_host` 经 gRPC 触发时改为
   **逐台一行**且 `Target` 与 CLI 同形（这正是上面第 5 条能成立的前提）；`audit.result` 不再装散文——
   `approval_kickoff` 写 `success`（档位没丢，在它 `Target` 指向的 approval 行上）、未结算 quorum 写
   token `quorum_pending`、`rest_gate` 不再把门禁消息拼进该列（消息回到响应与一行 INFO 日志；门禁消息
   里可能有通道输出，不该冻进 WORM 行）。两份引擎的 `audit.action`/`result` 列注释改成真词表，
   并有守卫与常量集**双向相等**。`audit.Record` 现在遇到词表外的值会 **warn 但照写**。
7. **门禁判定第一次真的进审计链**（PR #154）。每个 run 按 pre_apply / post_batch / post_apply /
   post-rollback 落 `gate_check` trace 行，挂在 **change id** 上——引擎自生的临时 run id 不是 `runs` 的行，
   第一版每条都撞 `trace.run_id` 外键，而「审计没写进去」按设计不冒泡，所以现象是一行日志 + 空面板
   而不是红（靠一条走 loopback 的接缝测试才看见）。回滚后体检用 `output.stage=rollback` 区分，
   phase 仍是 `post_apply`。引擎自己的 id 作为 `output.exec_run_id` 留在行里以便与 batches/steps 证据对齐。
   **写失败只 log、绝不翻转判定**。渲染侧零改动，`TraceTimeline` 自动多出这些行。
8. **API 的新增与扩展全是加法式**：
   - `GET /changes/{id}/approvals`（新读路径，PR #117）返回**一条链**：`approvers` / `min_approvers` /
     `decisions[]` / `plan_hash` / `stale`。`stale` 为真表示「你投的这票建在一版已经过去了的计划上」，
     由服务端与 run 当前 `PlanHash` 比对得出；run 自己没有计划哈希时**不判过期**。
   - `GetChange` 的 `include_plan=true` **第一次生效**（PR #155）：`message Change` 新增 `plan = 13`。
     默认不带、`ListChanges` 永不带，故既有调用方的 payload 与已提交的 wire 契约逐字节不变。
     无存量计划或 `plan_json` 不可解析时返回 `nil` 计划而非报错——「还没有计划」是 draft 的真实状态。
   - `/system/batch-status` 多发 `steps` 数组，并把 `batch_id`（行 id）在服务端解析成 `batch_no`。
   - `/system/cluster-status` 新增 `cluster_enabled`，并支持 `?capability=<名>` 在服务端收窄 `nodes`。
   - `GET /changes/<id>/events` 新增（SSE，`text/event-stream`），事件取自 `WatchChange` 订阅的**同一条总线**。
   - `GetTrace` 补回 `actor` / `target` / `detail`：此前两处行映射把 `TargetHost` 写成 `t.Actor` 并丢掉
     整个 `Detail` payload，所以审计页的证据片段对 trace 行恒空、控制台说不出事件跑在哪台机器上。
9. **移动审批深链的重复点击不再长得像失败**（PR #141）。已消费的 token 若仍绑定到审批已终结的 run，
   返回 **409 + 收据**（`decided` / `decision` / `run_id` / `decided_by` / `decided_at`），其余一律维持扁平 401。
   选 409 还有一个实际理由：前端对 401 会清 token 跳登录，操作员就看不见这句话了。
   **披露面没有扩大**：从未被服务端真实签发过的 token 走不到任何命中，仍只得到单字段 401
   （由 `assert.Len(out, 1)` 钉住）——否则这条路径会变成枚举 run 状态的探针。
10. **ChatOps 从只出变成出入**（PR #150）。三个平台的回调验签 + `/levee approve|reject|status` 真 handler，
    走与控制台/CLI/深链**同一个审批状态机**。三条要点：bot 没有 `secret` 就**不挂入向路由**（出向镜像照旧，
    启动日志点名说明，「没有入向」是说出来而不是被一次无人应答的点击发现）；回调路由的 Bearer 豁免做成
    **每路由**而非网关级（全局开 `MetricsPublic` 会同时把 `/metrics` 公开）；`identity_map` 解析不到或为空
    **一律拒绝**，不猜、不落到共享主体。**聊天是新的输入通道，不是新的权限来源。**
11. **新增 `levee tenant purge <tenant-id>`**（PR #156）。只删**终态且从未产生 trace** 的 run 及其
    `run_assignment` 行。三面门禁：租户状态必须是 `deleted`；空 tenant id 直接拒绝（`tenant.enabled: false`
    时全库行的 `tenant_id` 都是空串，按空串清理等于清掉整个单租户库）；`--json` 下必须显式 `--yes`。
    `trace`/`audit` 有 `BEFORE DELETE` 的 WORM 触发器，**删不掉也不该删**，所以输出明说「删了 N 行 /
    因 WORM 保留 M 行 / 非终态保留 K 行」，一行都没删时打印 `Nothing was removable`。purge 成功会写一条
    `audit.action = tenant_purge` 留痕。
12. **`--node-capabilities` 只在 `--cluster` 下有意义**（PR #161）。单独给出即启动失败并点名原因——
    单机 SQLite 进程没有 `cluster_nodes` 表可写，「收下但无处落」正是这一列长期空转的成因。
    能力现在报得上去、重连会刷新（心跳 upsert 的 `ON CONFLICT` 补上了该列）、`?capability=` 查得动，
    但**派发刻意不按能力路由**（仍按负载 / `--cluster-dispatch-capacity` / epoch），这一条写在旗标说明、
    `docs/deployment.md` §12、`docs/levee-api.md` 与控制台界面上。
13. **Helm：单节点 PostgreSQL 成为一等公民**（PR #158）。PG 管道改为按「操作者有没有要求 PostgreSQL」
    启用，不再看 `mode`；DSN 走 Secret → `LEVEE_DATABASE_DSN`。根因在配置侧：`database.dsn` 是
    `DatabaseConfig` 里唯一没登记进 `LEVEE_*` env 绑定表的叶子，所以那个环境变量**静默读不到**，
    单节点用户只剩「把 DSN 明文写进 `config.yaml`（即写进 ConfigMap）」一条路。
    `externalSecretName` 与 `postgres.dsn` 同时给出时**外部完全优先**。`driver: sqlite` 却启用 PG 时
    Chart **不改写操作者已写明的取值**，由 `config.Validate` 大声拒绝启动。
14. **贡献者侧两道新门禁**：① `browser-check` 进 CI（ubuntu + windows 双腿，挂进聚合 `needs`），
    `BROWSER_CHECK_REQUIRE=1` 下「找不到浏览器/驱动」一律判红——一个会静默跳过的绿色构建意味着
    「没人跑浏览器检查」；② `make web` 拒绝从 **CRLF 工作副本**构建：`@vitejs/plugin-vue` 把源码字节
    算进每个组件的 scoped 样式 id（`data-v-<hash>`），同一份 `ChangesView.vue` 在 CRLF 与 LF 下产出
    **不同文件名**的 chunk，本地无症状而 CI 永远判 stale。

## Security

- **写侧准入补齐**：见 Behaviour changes 第 4 条。这 8 个 RPC 的缺口与读路径、`plan`/`apply`/`rollback`/
  `approve`/`reject` 的既有判定是同一套矩阵，本批只是把「谁能改生命周期」也纳入它。
- **两个 REST-only 端点接上门禁**（PR #134）：`/system/cluster-status` 与 `/system/batch-status` 此前
  **直读 store、不经过 service**，因此不受服务层门禁约束。**订正一条错账**：roadmap 原登记四个端点裸奔
  （含 config / doctor），逐个核 handler 后只有两个是真的——另三个都委托给 SystemService，服务自己有门禁。
  `batch-status` **按 run 自己的环境**判，且 **404 必须先于 403**：未知 id 若拿去判环境，会把空环境解析成
  `default_env`，让有全部权限的主体因**打错一个 id** 收到 403。
- **入向验签 fail-closed**（PR #150）：Slack `v0:ts:body` HMAC（5 分钟新鲜度）、钉钉/飞书 `timestamp\nsecret`
  构造（1 小时容差）、1MB body 上限、时间戳缺失即拒。验签失败返回 401 且**不进路由**。
- **`gosec` 报告的一次误报按既有惯例处置**（PR #150）：新代码第一次把外部输入（`r.Body`）灌进 chatops 包，
  让 taint 分析第一次把 `httpclient.go` 的两个 sink 连到污染源，报出 2 条 G704——那两条在 master 上同样存在、
  且同一份代码在 v2.28.0 下与 master 完全同比。判定为误报（URL 恒为配置的 webhook，聊天文本只进 POST body）。
  处置是**逐行 `#nosec G704` 并写明理由**，而不是把 G704 加进 CI 排除清单——后者会在将来掩护一个真实的
  URL 污染型 SSRF。同批撤掉一处**无效的豁免**：`internal/state` 的两条拼接语句上写的 `#nosec G202` 实测
  零命中，豁免注释压住一个不存在的问题，代价是将来真出现同码问题时它会被一起静默掉。
- **凭据面**：`LEVEE_DATABASE_DSN` 现在真的可达（见第 13 条），因此 Helm 部署不必再把 DSN 写进 ConfigMap；
  DSN 的输出面沿用上版本的 `state.RedactDSN` 口径。
- **依赖 bump 不含安全公告**（PR #165）：`golang.org/x/crypto v0.57.0 → v0.58.0`、
  `aws-sdk-go-v2/config v1.33.4 → v1.33.9`、`service/kms v1.61.1 → v1.61.4` 三条来自 dependabot，
  PR 正文与标签里都没有公告号，因此**不记为安全补丁**。`go` 指令仍为 `1.26.9`（未变）。
  切版基线上 `govulncheck` / `trivy` / `gosec` 三条腿均 success。
- **CI 工作流的版本锁步**（PR #164）：`codeql-action` 的 `init`/`autobuild`/`analyze` 三条 pin 一起升到
  v4.38.3——`init` 在同 job 内安装 CLI、后两条复用同一 runner 上已装的 CLI，单边升级会红
  （`Loaded a configuration file for version 'A', but running version 'B'`）。

## Known gaps after this snapshot

- **`levee tenant purge` 的授权范围刻意小**：`credentials` / `targets` / `inventory_groups` 不在批准范围内，
  命令一律不碰；「连证据一起清」（purge `trace`/`audit`）是另一个产品决定——它要把 WORM 从默认承诺改成
  可选豁免，而 `verifyStoredPlanHash` 与审计链的取信前提会随之改变。
- **派发不按能力路由**（刻意，非漏项）：`internal/dispatch` 仍按负载/容量/epoch 选节点。理由是按能力路由
  会把不具备该能力的节点饿死在队列里，而「节点声明了什么」今天没有权威来源可校验。
- **`agent.MasterClient.Deregister` 的接口注释仍承诺「master 应把该 Agent 从注册表移除并重新分配在途任务」**，
  而唯一实现只做 `registry.Deregister`，没有任何重分配。这不是补一句代码的事——要先有任务下发通道
  （`agent start` 仍是进程内，proto 无下发通道）。注释保留原样，因为它写的是目标语义，而差距已在
  roadmap 与本节登记，不能再被当成「已经做了」。
- **`internal/permission.PermissionChecker` 自带的拒绝记录器仍无生产调用点**，且其占位 run id 受 trace 表
  外键限制写不进去；生产路径是 `internal/authz`。
- **工作流 `input:` 仍未接成单一真源**：本批只加了编译期如实告警 **LE004**（声明了 `input:` 块、
  或任意 step 参数里出现 `{{input.x}}` 时提示后果与真实替代路径）。接成取值注入是独立功能
  （解析时机、类型强制、trace 脱敏、参考校验），不在本批。
- **roadmap 交互层深色模式与列个性化已落地，只剩「密度档位」未做**（判空命令：`web/src` 内 `density`
  与「紧凑」零命中）。
- **自然语言双语定档为 zh/en，且现在不做**。真正的工程项是 `internal/docgen` 的**多目标生成**——
