# v1.13.0 Release Notes

**Release Date**: 2026-09-08

## Overview

This release delivers the two flagship designs that close LEVEE's biggest
stated-vs-delivered gap: **the execution engine is now wired into serve
(design A)** — plan → approve → apply is a real, audited, executing
pipeline — and **cluster failover takeover (design B)** — a crashed
executor no longer leaves its change rotting in `running` forever.
Both designs shipped with full acceptance suites (loopback + real-PG
e2e) and honest boundary documentation.

## New Features

### 1. Execution engine wiring (design A, `internal/wiring/`)

- **Plan persistence + plan_hash binding**: `PlanChange` persists the
  generated plan artifact on the run (`plan_json`, schema v3) alongside
  `plan_hash`; apply executes EXACTLY the approved plan. Runs without a
  persisted plan are refused (never a silent status-only fake success).
  Hash drift after approval is refused with guidance to re-plan.
- **Assembly factory + explicit opt-in**: `wiring.NewEngine(store,
  With*...)` promotes the "production-grade assembly recipe" from the
  e2e drills into production code. `serve --engine-enabled` (default
  **off**); off = behaviour identical to v1.12.
- **Execution closure + evidence persistence**: apply runs the
  ClosureRunner synchronously (ssh/local channels, inventory frozen-host
  guard, cmd/human/slo gates with fail-closed defaults, automatic
  rollback, batch abort policies); batch/step evidence rows land with
  exit codes and streams; retry supports host subsets with batch-row
  reuse; concurrency cap fast-fails the N+1st apply.
- **CLI engine paths**: `levee plan <run-id> --targets h1,h2
  [--dry-run]` and `levee apply --engine-enabled` share the SAME
  in-process ChangeService path as serve (approval/frozen/plan gates
  shared, not re-implemented). `--force` maps to auto-approve;
  refusals exit 4, execution failures exit 1.
- **Ops surface**: `--engine-max-parallel-runs` (default 4),
  `--engine-gate-prometheus` (unset = slo gates fail closed).

### 2. Cluster failover takeover (design B, `internal/takeover/`)

- **Execution fencing**: new `run_execution` lease table with a
  monotonic epoch sequence. Cluster-mode executions must claim a lease
  before their first dispatch (refused otherwise — no invisible
  takeover candidates); heartbeats renew at TTL/3 independently of step
  progress; `Owns` re-validates AND renews (structurally closes the
  check→takeover→persist TOCTOU); step dispatch and evidence
  persistence are both gated; the evidence of a superseded executor is
  discarded rather than persisted.
- **Fenced-out executors never roll back**: losing the lease surfaces
  via the `engine.ErrFencedOut` sentinel which the closure recognises
  and SKIPS the automatic rollback for — an undo dispatch from a
  superseded executor is exactly the remote double-write fencing
  exists to prevent (the rollback path itself is deliberately
  uncancellable, so the fence signal must never be a ctx cancel).
- **Takeover loop** (leader-exclusive, idempotent under three guards:
  convergent election view + per-run takeover lock + running→
  interrupted status CAS): settles crashed executors' runs to the new
  terminal **`interrupted`** with a full audit trace
  (`interrupted_by_takeover`), marks non-terminal step rows
  defensively, deletes the lease row, and never re-executes anything.
  Orphan scan (running runs with no lease, 5-minute grace) closes the
  CAS→Begin crash-window dead zone.
- **`interrupted` vocabulary**: retryable via `RetryChange` (explicit
  re-drive through the full approval/fencing/evidence gates), archived
  allowed, cancel refused; WatchChange treats it as terminal; frontend
  label/color; UI retry button on the changes dashboard.
- **Observability**: `levee_takeover_events_total{result}` counters.
- **Flags**: `--cluster-takeover-interval` (default 10s; ≤0 disables the
  loop, never the fencing), `--cluster-exec-lease-ttl` (default 30s;
  bounds post-crash detection latency, NOT execution duration).

### 3. Authentication (optional)

- **OIDC SSO**: any standard IdP (Keycloak/Zitadel/Entra ID/Okta);
  authorization-code + PKCE browser flow against the gateway.
- **GitHub SSO**: server-side code exchange (GitHub is not an OIDC
  provider); LEVEE-local HS256 session tokens; team→role mapping.
- **Named multi-token auth**: repeatable `--auth-token name=secret`,
  the authenticated subject overrides client-asserted `X-Acting-As`.

## Fixes & Hardening

- **Terminal-write CAS everywhere** (B1): late executors can no longer
  overwrite a state another actor already wrote; event publication
  belongs to the CAS winner.
- **Convergent election unconditional re-election**: a node that
  self-elected leader on its own partial view (join race) is now always
  corrected on the next sync — previously it stayed wrong forever.
- **PG new-database bootstrap failure**: an inline `--` comment
  containing `;` in pgschema.sql cut the CREATE TABLE mid-comment
  (SQLSTATE 42601); the PG splitter is now a full state machine
  (string literals, `''` escapes, inline comments) with the embedded
  schema pinned by structural tests; the SQLite sibling hazard is
  documented and pinned.
- **Cluster-mode test isolation** (CI): packages sharing the CI
  postgres database no longer run destructive TRUNCATE fixtures in
  parallel.
- **Runner-clock flakiness eliminated**: probe-gate latency assertion
  no longer requires strictly positive readings on virtualised clocks;
  the lock concurrent-acquire smoke runs on `:memory:`.
- **401 UX**: unified token-clear + redirect on the web client.

## Security

- x/crypto v0.56.0 + go1.26 toolchain (closes the last two dependency
  CVEs; ReverseProxy migrated to `Rewrite`).
- REST method validation on state-changing routes (POST-only; GET
  cannot pause a change any more).
- SSH `become_user` POSIX-quoted (sudo -u injection closed).
- `/metrics` requires Bearer auth by default; `--metrics-public` opts
  out for credential-less collectors.
- Credential blob versioning, random-ID hard-fail policy, audit
  redaction vocabulary 8→16 words, permission-matrix strict actions,
  WORM duplicate-write error semantics, SQLite synchronous mode
  configurable (full audit-persistence story). See CHANGELOG for the
  full SA-xxx ledger.

## Testing

- CLI command family e2e (12 files; cmd coverage 45.9% → 66.8%).
- Frontend unit-test baseline (vitest + jsdom, 40 cases).
- Integration suite re-aligned to engine semantics; serve-level gRPC
  acceptance (real execution / rolled_back / tamper refusal) and the
  two-node takeover e2e (crash convergence, zombie zero-pollution,
  single-writer under concurrent takeovers) — all against real
  PostgreSQL in CI.

## Known Limitations (honest boundaries)

- Cross-node scheduling, resumable re-execution (skip-completed), and
  cross-node rollback snapshots remain backlog items by design.
- A zombie executor can still complete a remote side effect that was
  in-flight when the takeover settled (identical exposure to a
  single-node crash); fencing eliminates the DB-level double-write,
  not remote idempotency.
- Manual `RollbackChange` is outside the fencing perimeter (does not
  transit `running`): a node dying mid-manual-rollback leaves the run
  in its source state for an operator to re-issue.
- Rollback snapshots (`rollback.SnapshotManager`) remain built-but-
  unwired (no production consumer); snapshot-to-Postgres is future work.
