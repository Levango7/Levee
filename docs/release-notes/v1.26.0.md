## Overview

自 v1.25.0 以来，LEVEE 的主线从「把已有能力做齐」转向**两件更要紧的事**：把数据库变更
做成一张**可出示的单**，以及把**断网/分区**这件运维现场的事从文档变成可执行的策略。
本版按主题分（60 小节，计数与 CHANGELOG 逐条对应）：

1. **数据库变更发布单（DB Change Ticket，7 节）**——本版的主线。一个变更的 SQL 批、
   审核结论、回滚计划、窗口、审批链、执行证据与审计链完整性，第一次能合成**一张单**：
   `internal/dbchange` 读模型 → `levee dbchange show` CLI → `GetDBChangeTicket` gRPC →
   `GET /changes/:id/ticket` REST → Web `/changes/:id/ticket` 页 → 导出 Markdown →
   打印/另存为 PDF。整条链上守的是同一件事：**读不到不等于没有**——计划制品不可读时
   说「未知」，legacy 审批不冒充「绑定当前计划」，审计校验出错不冒充「没有 trace 记录」。
2. **断网策略与复现探针（4 节）**——Q1 分区期拒绝新 apply/审批（fail-closed）；
   Q3 只读白名单（逐条裁决、每条带理由）+ 控制面可达性标记（运行计数是「未知」不是 0）；
   Q4 恢复四步对账工具（两套：部署侧脚本 + 容器靶场同构版，重驱都要显式确认）。
   另加**自动复现探针**：两条「未复现、只能等复发观察」的 P1 现在每天自动去撞，
   复发即留证据（频率、完整 stderr、Chrome 进程自身的输出）。
3. **SQL 审核链与门禁 DSL（6 节）**——`levee sqlreview` 规则引擎首版（20 条自撰规则）；
   审核裁决进计划漏斗（fail 不进产物、warn 随 plan_hash 固化）；离线演示脚本与手册；
   `k8spolicy` 门禁终于能在 YAML 里写出来。
4. **云原生变更治理（3 节）**——S1 纯函数策略引擎 + 门禁适配器（fail-closed）；
   S2 通道插件（Kubernetes 成为可治理的变更目标，核心零行改动）；设计提案与平台矩阵。
5. **灾备与跨机房（5 节）**——裸机灾备验收三场景容器靶场（机器断言 + 诚实契约）；
   跨机房 `region` 放置成为**派发判据**（文档承诺 → 代码事实）；inventory region 标签闭环；
   跨机房拒绝诊断点名 offending batch 并给可操作补救。
6. **推送与通知（4 节）**——A-3 的后半：`serve` 真的能发推送（APNs/FCM 凭据接入守护进程）、
   审批创建即通知审批人、设备注册表跨进程可见。
7. **契约、词表与门禁（11 节）**——wire 契约夹具补齐前端实调端点；JSON 空集合从
   `null` 统一为 `[]`（六处）；命令树负断言守卫（`levee schedule` 这类「必须不存在」
   的路径变成机器可查）；账本断言机器化扩容；blocked-items 结构门禁；roadmap 状态列
   收成一列 + 门禁；台账-代码一致性门禁扩面（43 条 claims）。
8. **其他修复（12 节）**——含**两处行为级修复**（见下「契约与行为变更」）：
   `RollbackChange` 的 `dry_run` 此前会**真的执行回滚**；`levee rollback` 此前
   **从来没有回滚过**。另有 REST `WriteTimeout` 砍掉同步长操作的响应、
   `RunEventStore.UpdateRun` 的读-改-写竞态、assignment 陈旧度改按 store 时钟比较、
   执行结果不确定的六种判定（`not_started`/`in_flight`/`complete`/`partial`/`missing`/
   `unrecorded`）、运行期通道插件「一插件多类型」等。
9. **文档与账本卫生（7 节）**——roadmap 表格畸形行修好（`状态` 列现在真的会渲染）、
   `CONTRIBUTING.md` 的 CI 计数订正（24 → 实测 26）与「零 check」的第二种来源、
   blocked-items 的 G-1/G-3/D-3 定档、板约定收口等。
10. **依赖与工具链（1 节 + 1 处）**——`golang.org/x/net` v0.60.0 → v0.62.0（修
    CVE-2026-78661）；`go` 指令 1.26.10 → 1.26.11（收口 GO-2026-6859）并升
    `golang.org/x/crypto` 到修复版。

## 契约与行为变更（升级前必读）

### 行为修复（可能影响既有调用方）

- **`RollbackChange` 的 `dry_run` 现在是真预览**。此前服务端**从未读过**
  `req.GetDryRun()`：控制台的「补救 → 先预览再确认」会**真的执行回滚**
  （补偿派发到生产主机、run 状态被改写、审计链留下 `rollback` 记录），而紧接着的
  「现在补」又因状态已变成 `rolled_back` 被准入检查拒绝。修复后：`dry_run` 不改状态、
  不写审计链、不发事件、不铸 rollback run id，响应回报 `rolledBackHosts` /
  `skippedHosts` 与一条点名缺口主机的 message。
- **`levee rollback` 现在真的回滚**。此前它只把 run 写进一个没人消费的状态；
  现在它派发补偿，并补上 `rollback --dry-run` 与对应 POST 的 wire 契约。

### 新增接口

| 面 | 新增 |
|----|------|
| proto | `ChangeService.GetDBChangeTicket`（返回 `DBChangeTicket` 七段） |
| proto | `SystemStatus` 新增 `control_plane_reachable` / `run_counts_available` / `partition_reason` |
| REST | `GET /changes/:id/ticket`（可加 `?format=markdown` 或 `?format=html`，后者可加 `&print=1`） |
| CLI | `levee dbchange show <id>`（`--format text\|markdown\|html`、`--output`） |
| CLI | `levee sqlreview --change <id>`（复算变更携带的 SQL，并与计划固化结论比对） |
| CLI | `levee target label set/unset`、`levee target history --remote` |

### JSON 空集合统一为 `[]`

`trace --verify` / `diff` / `team list` / `group list` / `audit export` / `audit verify` /
`target list` / `target history` / `diagnose` 的空集合从 `null` 改为 `[]`。**依赖
`null` 判断「无数据」的调用方需要改**：空数组才是「没有」。

### 其它

- `go.mod` 的 `go` 指令升到 **1.26.11**（构建需要该版本工具链）。
- `golang.org/x/net` 升到 v0.62.0（CVE-2026-78661 已修）。

## 诚实边界（本版**没有**做到的事）

- **发布单是只读视图**：不新增审批、回滚或执行写操作；审核结论是**计划时固化**的那份
  （`plan_hash` 绑定、审批签下）。「规则集后来变了没有」由
  `levee sqlreview --change` 回答——它是一次**测量**，不是第二次审批。
- **窗口无法回放**：变更窗口是工作流声明、plan 期校验，run 行不持久化该事实，
  所以发布单**不能**从库里回放「这次变更是按哪个窗口放行的」（发布单里如实这么写）。
- **两条 P1 仍未复现**：`internal/calendar` 在 windows-latest 上的偶发访问违例、
  `browser-check` 在 windows-latest 上的偶发失败。两者现在都有**每日自动复现探针**
  在盯（复发即留证据），但**探针不等于修复**——台账状态仍为 open。
- **k8s 通道的不可逆动作**需要 `allow_irreversible` 白名单与运行时确认，默认拒绝。
- **信创硬件（ARM/国产数据库）**与 **schedule 窗口**等仍按 `docs/blocked-items.md`
  的现状记账，本版没有改变。
