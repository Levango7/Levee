# v1.10.0 Release Notes

**Release Date**: 2026-08-23

## Overview

This release is a security and operational hardening milestone. Following a comprehensive audit, all Critical and High severity findings were fixed, the gRPC REST gateway gained production-grade security (auth gate, rate limiting, request tracing), and the plugin sandbox now enforces resource limits on Linux via cgroup v2. CI additionally runs gosec and trivy security scans.

## Security Hardening

### Authentication & Access Control
- **Auth startup gate**: `levee serve` refuses to start without a token unless `--insecure` is passed explicitly (or via `LEVEE_TOKEN` env var)
- **CORS deny-by-default**: wildcard origins are no longer implied when the origin list is empty; `*` must be configured explicitly
- **Constant-time token comparison**: Bearer token validation uses `crypto/subtle`
- **TLS plaintext warning**: serving without TLS logs a prominent warning at startup

### Credential Handling
- User module passwords are no longer passed on command lines; credentials are uploaded as temp files and consumed via `chpasswd < file`, keeping secrets out of process argv and SSH logs

### Plugin Sandbox (Linux)
- cgroup v2 based enforcement of plugin memory limits (`memory.max`) and CPU quotas (`cpu.max`)
- Plugin processes are attached to a dedicated `levee-plugin-{pid}` cgroup
- Graceful degradation: when cgroups are unavailable the wall-clock timeout remains the safety net
- Validation tests under `internal/plugin/sandbox_linux_test.go` (skipped without cgroup write access)

## REST Gateway Improvements

- Full RESTful routing: `/api/v1/changes/{id}`, `/templates/{id}`, `/targets/{id}` with correct `/:id` path parsing
- Token authentication middleware for HTTP endpoints
- Global rate limiting (token bucket): `--rate-limit` / `--rate-burst` flags, 429 responses with `Retry-After`
- Request ID tracing: `X-Request-Id` header echoed and propagated through gRPC metadata (`x-request-id`)
- Mobile approval deeplink endpoints
- Standard gRPC health service registered (`grpc.health.v1`), SERVING/NOT_SERVING transitions on start/stop

## Bug Fixes

- **GetLogs** now honors the `levels` filter (stdout→INFO, stderr→ERROR) instead of returning everything
- **GetTrace** honors an explicit `run_id` in the request over the change-wide default
- **ArchiveChange/purge**: trace deletion during purge was silently failing against the WORM constraint; WORM trace preservation is now explicit documented behavior
- REST gateway `/:id` routes previously failed with 400 due to a leading-slash trimming bug

## API Semantics Notes

- Multi-tenancy: tenant isolation exists as a store-layer contract but is not wired into the daemon path in this release (MVP scope decision; revisit in V2)

## CLI Changes

New `serve` flags:

```
--token string        API auth token (falls back to LEVEE_TOKEN env var)
--insecure            allow serving without auth (dev only)
--cors-origin strings allowed CORS origins (deny-by-default)
--rate-limit int      REST requests per second (default 200, negative disables)
--rate-burst int      REST burst size (default 400)
```
