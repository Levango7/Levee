# v1.19.0 Release Notes

**Release Date**: 2026-10-06（附注 tag `v1.19.0` 切于 2026-10-06 00:19 +0800，指向 `ddad079`；主体内容进入 master 的时间为 10-04 至 10-05）

## Overview

The last spec-registered vocabulary with zero producers is now wired:
`allow_irreversible` is a real compile-time gate. Any step whose
reversibility verdict is irreversible — an explicit `irreversible: true`
declaration, or a hit on the engine's inherent destructive vocabulary
(`pkg.remove`, `file.delete`, `user.remove`, `mysql.replica_switch`,
`mysql.pt_osc`) — must be listed in the workflow-level whitelist, or
compilation fails with LE082. An absent list authorizes nothing, not
everything. **This is a behaviour change**; migration notes below.
Per-item detail in [CHANGELOG.md](../../CHANGELOG.md).

## The gate (V14 / LE082)

- Parser / AST: a workflow-level `allow_irreversible` list of `module.action`
  entries (format-checked with LE101). The IR artifact
  (`levee compile --ir`) carries `workflow.allow_irreversible`, so the
  compiled artifact itself records what this compilation authorized. The
  emitter round-trips the list sorted and byte-stable.
- Validator rule V14: the verdict priority mirrors
  `executor.IrreversibleChecker.Check` — explicit declaration first, the
  inherent vocabulary second. Mixed step lists report only the unlisted
  offenders.
- Single source of truth: `dsl.DefaultIrreversibleActions()` /
  `dsl.IsInherentIrreversible()` is the one list of inherently destructive
  actions; the plan generator's checker registration and the compile gate
  both consume it, so the two layers cannot disagree on what is irreversible
  by nature. The vocabulary lives in `internal/dsl` rather than
  `internal/executor` (where it was first written): `internal/executor`
  already imports `internal/dsl`, so the reverse edge would close a cycle —
  and "which actions destroy something" is language knowledge, the same
  category as the `actionSignatures` table in `typechecker.go`.
- Defense in depth: `plan.Generator.Generate` enforces the same rule on the
  server path (wiring.GeneratePlan parses the document and calls the
  generator directly, without the validator) — the same shape as the LE097
  plan-time gate.

## Migration (behaviour change)

Workflows with unauthorized irreversible steps that compiled before now
fail at compile / import / plan with LE082. The remediation is explicit
intent — list exactly the irreversible actions the workflow is meant to
run:

```yaml
allow_irreversible:
  - mysql.replica_switch
```

If you cannot list it, it should not run — that is the point of the gate.
Already-approved plans are unaffected: the gate acts at compile/plan
generation and does not retroactively revoke approved artifacts. The two
shipped example documents were migrated and remain guarded by
`TestShippedExamplesCompile`.

## Runtime protection unchanged

The two existing runtime layers stay exactly where they were: the
module-level `confirm=yes` hard gate (mysql.replica_switch refuses an
unconfirmed switch at execution time) and the plan-side escalation of
irreversible steps to high approval. The compile gate adds the earliest
possible line — the workflow never enters the pipeline at all.

## Also in this snapshot (merged after v1.18.0)

The tag cuts from master `fd0f697`, which carries more than the whitelist work
described above. Per-item detail lives in [CHANGELOG.md](../../CHANGELOG.md);
the headline additions:

- **`post_batch` gates really gate now.** `GateSpec.Batch` had no producer, so a
  batch-level check was hash-bound but never materialised or executed. Routing is
  fixed across all three declaration sites, so a failing batch check now stops the
  rollout (behaviour change; migration note in the CHANGELOG).
- **Change attribution and environment fidelity.** All three creation paths bind
  `run.Creator` to the verified subject; template instantiation no longer wipes the
  declared environment down to `permission.default_env`, no longer records `"grpc"`
  as the author, and writes the `create` audit row it always should have.
- **D-20 webhook notifications are wired.** `notify.webhook.enabled` is now consumed
  at serve assembly time (channel `webhook`) and attached through
  `wiring.WithNotificationManager`; rollback-grade notifications are delivered for
  real, signed via `LEVEE_WEBHOOK_SECRET`, and an enabled-but-unusable channel
  refuses the boot. Scope stated honestly: rollback grading is today's only producer.
- **Delivery-artifact version gate.** `scripts/check_release_versions.py` (run by
  `validate_delivery.sh` before helm) requires `appVersion == image.tag`, requires the
  referenced version to exist as a tag on the *remote*, and rejects a CHANGELOG section
  claiming a release newer than the newest tag unless it says so.
- Fixes folded from the unreleased block: audit-chain sealing on write plus batch
  traversal, approval-level vocabulary converged onto a single source, and `levee new`
  producing a run that can actually be planned.

**Known limitation registered in this window (not fixed here):** command gates never
receive `GateInput.Channel` in the run path, so a declared `cmd` gate cannot execute
its check and fails closed — safe, but non-executable. Tracked in
`docs/product-roadmap.md`.
