# v1.15.0 Release Notes

**Release Date**: 2026-10-03

## Overview

This release closes every remaining disposition item registered after
v1.14.0 — the last "built but unreachable" surfaces either became real
capabilities behind a config face or were retired on the record, and the
2026-08-15 design review's 21 findings are now fully accounted for. No
known open defects; per-item detail in [CHANGELOG.md](../../CHANGELOG.md).

## ChatOps Approval Mirror, Wired

`notify.chatops.*` (enabled + a list of bots with
platform/name/webhook_url/secret/timeout) now assembles Slack / DingTalk /
Feishu webhook bots inside `serve`: approval lifecycle events (requested /
decided) are projected onto the chat channels where approvers already work.
The bridge occupies the observer slots, which were converted to **fan-out**
in v1.14.0 — enabling ChatOps alongside the Jira mirror delivers to both
instead of silently displacing one. Default OFF (zero assembly); a bot
missing its name/webhook_url, or an unknown platform, fails the boot naming
the offending bot.

## LLM Diagnosis: Corroborated Convergence

`internal/diagnosis/llm_diag` is now wired into the Diagnose RPC when
`ai.llm` is enabled, and its convergence criterion was inverted: the loop no
longer stops on a single self-reported "converged" answer. It requires the
hypothesis to **repeat across two consecutive turns** (whitespace/case
normalized) before the self-report is honoured — the first turn can never
converge, and an oscillating model exhausts its turns instead of converging
on noise. The result now carries `ConfidenceSource: model_self_report`,
stated explicitly so a model's own estimate can never silently read as a
verified measurement downstream (it feeds approval-tier decisions). The
declared-but-never-assigned `StatusInconclusive` was removed. A converged
result enriches the rule-based report; failures and non-convergence keep
the rule-based answer (an LLM outage cannot take the RPC down).

## Effect-Learning Loop Closed

`internal/recommend/feedback` had three defects that made the loop hollow;
all three are closed:

- **A copy-vs-pointer defect**: `Record` stored a value copy and returned a
  pointer to a local copy, so `Learn`'s PatternID stamp landed in a record
  nobody could read back (every stored record showed an empty PatternID).
  Records are now stored as pointers.
- **Amnesia**: state (records, per-pattern stats, synthesized patterns and
  incidents) now persists as an atomic JSON snapshot under the data dir and
  is restored — and re-added to the knowledge base — on boot. A corrupt
  snapshot degrades to a fresh start (learning is auxiliary state, never
  the system of record).
- **A disconnected loop**: `Learn` wrote patterns into a knowledge base
  the recommend engine never saw (serve passed none; the engine built a
  private one). serve now constructs ONE shared `KnowledgeBase` for the
  engine and the learner, and `levee converse` loads the learned patterns
  read-only via `feedback.LoadInto`.

Every apply verdict (success / failure / rollback) is now recorded as a
`FixOutcome` from `change_service`; successes synthesize new patterns,
failures count against known ones. Cancellations are deliberately not
recorded — abandoning a change is not an outcome of a fix.

## compat: D-08 Mapping Redefined, Oracle-Guarded

The Ansible import layer's flat mapping (four phantom actions, state-blind:
`apt state=absent` became `pkg.install`) is replaced by a state-aware
resolver: apt/yum map by present/absent/latest to install/remove/upgrade,
`service` maps to the real six svc actions by state or enabled, `user` maps
to add/remove by state. Constructs with **no faithful LEVEE action** (the
`file` module, the `group` module, unknown states, state+enabled combined)
are refused fail-closed with the alternatives named in the error. A new
external oracle test walks every output of the resolver against the REAL
executor registry (`executor.DefaultExecutor()`) — phantom actions can no
longer get in.

## `levee run --shell` Registered

The MVP's bare-shell runner is now a CLI command — explicitly labelled a
LOCAL DEBUG ESCAPE HATCH: platform shell, timeout, structured output
(`--json`), the child's exit code propagated via the established `[exit=N]`
contract (timeout = 8). Help text and the API doc both state plainly that
it does NOT go through plan / approval / batches and writes nothing to the
audit or trace chains.

## Documentation: All 21 Review Findings Accounted For

The 2026-08-15 design review's remaining six P2 items are closed:
`levee schedule` documented as V1 (current scheduling is drift patrol only);
spec §2.2 keyword lists gained `any`/`all` and `allow_irreversible`; the
REST endpoint table carries a core-endpoints-only note; `levee run` is
documented; §10.3 notes the mysql modules are implemented; the design §5.2
example is marked as a target-state (V1+) illustration. Unlinked packages:
**8 → 3** (only `diagnosis/topology`, the `compat` import layer and
`opsmesh` remain, all documented in the README capability table).

## Upgrade Notes

- `notify.chatops` is a new optional section; absent = zero assembly, no
  behaviour change.
- AI diagnosis requires `ai.llm.enabled=true`; convergence now takes at
  least two LLM turns (the first turn can never converge) — expect the
  reasoner to spend a second turn by design.
- Learned feedback state is written to `<data_dir>/feedback.json`; it is
  safe to delete (fresh start) but never the system of record.
