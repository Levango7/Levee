## Overview

v1.20.0 之后的第三批，共 **12 个小节**，三条主线：

1. **判据与词表收口（7 节）**——批次状态、分配状态、会话状态、`/system/status` 的中文标签与
   owning 常量落位，以及两条被机器守卫钉住的"两份词表/两份抄件"路径。这批的产出不只是文案：
   每处都补了**从常量源解析**的守卫（不是复述清单），并逐条做了变异检验。
2. **控制台重做（2 节）**——设计系统 + 双主题 + 全部页面重构；随后一轮"玻璃只上 chrome"的
   收尾（粘性顶栏、同心圆角、镜面内高光、三级回退）与 `Ctrl/Cmd+K` 命令面板。
3. **门禁级缺陷（3 节）**——CHANGELOG 结构守卫抓到了自己登记的那一类损坏；`release-gate` 的
   `unittest … | tee` 在 `bash -e` 下**吞掉一切断言失败**（这道门因此长期不会红）；`govulncheck`
   被 `go` 指令挡住（补丁级公告先于补丁工具链进仓）。同批收口 SA-007（服务层权限拒绝落审计链）与
   SA-011（凭据明文的调用点义务），并修掉"看板把工作流源当变更名显示"。

逐条细节见 [CHANGELOG.md](../../CHANGELOG.md)。

## Behaviour changes (read first)

1. **`go` 指令升到 1.26.9（最低工具链要求）**。`govulncheck` 作业刻意按 `go.mod` 声明的工具链
   扫描，所以标准库类公告只能靠升指令收口。**对使用者的影响**：模块现在要求 ≥ go1.26.9，工具链会
   按需下载；**若本机 `GOSUMDB=off`，go 会拒绝校验要下载的工具链并硬失败**（`verifying module:
   checksum database disabled by GOSUMDB=off`）——把 `GOSUMDB` 交回 `sum.golang.org` 即可
   （本仓开发机实测：`goproxy.cn` 代理校验库，经它下载 + 校验正常）。CI 侧 11 处 `setup-go`
   全部改用 `go-version-file: go.mod`：`go-version: '1.26'` 的别名解析实测会取到滞后的
   1.26.8（加 `check-latest: true` 也一样）。
2. **`release-gate` 从此会真的红**。该步骤此前是 `python -m unittest discover … | tee /tmp/py.log`
   加一条"点名单 grep"，而 runner 默认 shell 是 `bash -e`（**没有 pipefail**）⇒ 管道退出码属于
   `tee`，**任何断言失败都不会让这道门变红**（点名单只堵"空收集"）。已加 `set -o pipefail` 并把
   两个判据分开记录、一起判死。含义要说清：这道洞自 2026-10-06 引入起就开着，期间被吞掉的红色
   **无法回查**；今后不会再有。
3. **看板的"变更名"换了来源**。`pb.Change.Label` 此前是 `run.WorkflowName` 的原文，而该字段的
   契约是工作流**源**（模板实例化的 run 里是整份渲染文档）——那一列显示的是一段 YAML。现在与 CLI
   共用 `dsl.DisplayName`：单行输入原样、可解析文档取声明的 `name:`、**不可解析则原样返回**。随之
   **`labelContains` 过滤的语义从"源子串"变成"名字子串"**；`WorkflowFile` 仍逐字携带源，取源的
   调用方不受影响。
4. **权限拒绝会留下审计行**（SA-007）。审计链里出现新的一类行：`Action=permission.denied`、
   `Result=denied`、`Actor=<被拒主体>`、`Target=<action>@<env>`、`RunID=''`。**审计导出/报表的
   读者会看到新的 action 值**；`RunID` 为空是设计（`audit.run_id` 无外键，无 run 的拒绝才写得进去）。
   逐行过滤（列表按环境隐藏行）**刻意不记**，不会出现"一页 200 行 = 200 条拒绝"。
5. **控制台整体换新**。`web/` 从 Element Plus 默认皮肤重建为设计系统 + 双主题（`--lv-*` 语义别名
   驱动，组件无 dark 分支），13 个视图全部重构；`internal/web/dist` 已同步刷新。旧的浅色默认皮肤与
   旧导航轨不再存在。

## Security

- **SA-007（权限校验缺少操作级审计）改判已修复**。生产判定在 `internal/authz`，此前拒绝时不记任何
  审计——"我们说过不"只活在调用方收到的错误里。现在服务层两个门（`authorizeResource` /
  `authorizeResourceRead`）在返回拒绝前落审计链；词表与行构造单点放在 `internal/audit/denial.go`，
  `internal/pause` 既有记录器改为委托它。接线由结构守卫钉住（`cmd/levee/serve_authz_recorder_test.go`）：
  摘掉那行**编译照过、行为测试全绿**，只有守卫会红。
- **SA-011（凭据明文生命周期）**：`RetrieveInto`（回调结束即清零，含 panic 路径）此前已在；本次把
  最后一处 `Retrieve` + 手写 `defer` 的生产调用点改成它，并新增全仓调用点守卫（每处 `.Retrieve(`
  必须是 `RetrieveInto` 体内或带 `NOTE(SA-011)` 所有权说明）。**边界照旧**：`CredentialRef.Password`
  是 `string`（不可清零），要抹掉需跨 ssh/winrm/grpc 改 `[]byte`，仍按设计搁置。

## Known gaps after this snapshot

- `audit` 表 `action`/`result` 两列的 schema 注释与实际写入值早已不符（注释写
  `success|failure|denied|error`，实际还写 `draft`/`rolled_back`/`archived`/`recorded; quorum pending`
  等，`rest_gate` 把截断消息拼进 `result`）——需要独立的一批审计词表收口（单一 owner + 列注释守卫）。
- `internal/permission.PermissionChecker` 自带的拒绝记录器仍无生产调用点，且其占位 run id 受
  trace 表外键限制写不进去（注释已如实写明）；生产路径是 `internal/authz`，本条不再影响合规面。
- 审计链的 `Rebuild` / `BuildForce` 仍**无生产调用点、无 CLI**——刻意留白（何时允许重链是运维决策）；
  "删除 vs 挤位"分辨不出（WORM 触发器是删除的防线）。
- 工作流 `input:` 块仍被解析进 AST 却零读取点（与模板 `parameters` 两套并行声明）——接单一真源还是
  从规范删除，属产品决定。
- `web/src/api/conversation.spec.ts` 的 `vi.resetModules()` 动态导入仍登记为既有的随机红风险。
- roadmap 交互层的两项 P0（模板实例化向导、部分回滚补救向导）未做。
