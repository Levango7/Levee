## Highlights

LEVEE v1.3.0 是 **Phase 2 — 平台化** 里程碑版本。在 v1.2.0 核心增强（KMS、变更日历、类型检查、SLO 门禁）的基础上，v1.3.0 将 LEVEE 从命令行工具升级为**可观测、可扩展、可协作的变更管理平台**：

- **F01 Web UI** — Vue 3 单页应用，7 个核心页面，go:embed 嵌入，零外部依赖
- **F03 插件系统** — 四类插件接口 + 子进程沙箱 + SQLite 注册表，用户可自定义扩展
- **F06 RBAC 增强** — 角色继承树 + ABAC 标签权限 + 权限缓存，从二维矩阵升级为多维策略
- **F09 ChatOps** — 飞书/钉钉/Slack 机器人适配，卡片消息 + 一键审批，变更协作闭环

## New Features

### F01: Web UI

Vue 3 + Vite + TypeScript 前端，通过 gRPC-Web 与 LEVEE 后端通信，go:embed 嵌入静态文件到单二进制。

**7 个核心页面**:

| 页面 | 路由 | 功能 |
|------|------|------|
| 变更看板 | `/changes` | 变更列表、状态过滤、详情查看 |
| 审批中心 | `/approvals` | 待审批列表、一键通过/驳回 |
| 实时监控 | `/monitor` | 运行中变更、批次进度、SLO 指标 |
| 模板管理 | `/templates` | 模板列表、参数预览、实例化 |
| 目标管理 | `/targets` | 目标机列表、可达性检查、分组 |
| 审计追踪 | `/audit` | Trace 浏览、哈希链校验、导出 |
| 系统设置 | `/system` | 配置查看、KMS 状态、健康检查 |

**CLI 命令**:
```bash
# 启动 Web UI（默认 :8080）
levee web --addr :8080

# 指定 gRPC 后端地址
levee web --addr :8080 --grpc-addr localhost:9090
```

**技术栈**:
- Vue 3.5 + Composition API + `<script setup>`
- Vite 6 + TypeScript 5.6 (strict mode)
- Vue Router 4 + 自定义 gRPC-Web 客户端
- go:embed 嵌入构建产物，单二进制部署

### F03: 插件系统

四类插件接口，覆盖 LEVEE 所有扩展点。子进程沙箱隔离执行，SQLite 注册表管理插件生命周期。

**四类插件接口**:

| 类型 | 接口 | 用途 |
|------|------|------|
| Channel | `ChannelPlugin` | 自定义目标机通道（如 Ansible、Salt） |
| Gate | `GatePlugin` | 自定义验证门禁（如自定义健康检查） |
| Module | `ModulePlugin` | 自定义执行模块（如数据库迁移） |
| Notifier | `NotifierPlugin` | 自定义通知渠道（如企业微信） |

**子进程沙箱**:
- 超时控制（默认 30s，可配）
- 内存限制（RLIMIT_AS on Linux）
- 崩溃自动恢复 + 重试
- stdin/stdout JSON 协议通信

**CLI 命令**:
```bash
# 注册插件
levee plugin register --name my-probe --type gate --path /opt/plugins/my-probe

# 列出已注册插件
levee plugin list

# 查看插件详情
levee plugin show my-probe

# 启用/禁用插件
levee plugin enable my-probe
levee plugin disable my-probe

# 注销插件
levee plugin unregister my-probe
```

**示例插件**: `examples/plugins/http_probe/` — HTTP 健康探针 Gate 插件，可编译为独立二进制。

### F06: RBAC 增强

从 v1.0.0 的二维权限矩阵（团队 × 环境）升级为多维权限策略引擎。

**新增能力**:

| 特性 | 说明 |
|------|------|
| 角色继承树 | 角色可继承父角色权限，支持多级继承，循环检测 |
| 细粒度策略 | Resource × Action × Condition 三维策略定义 |
| ABAC 标签权限 | 基于资源标签的属性访问控制，支持 `==`、`!=`、`in`、`contains` 操作符 |
| 权限缓存 | TTL 5min LRU 缓存，减少重复策略计算 |
| 条件表达式 | `env == "prod" && team in ["sre", "platform"]` 布尔表达式引擎 |

**CLI 命令**:
```bash
# 角色管理
levee rbac role create --name platform-admin --parent admin
levee rbac role list
levee rbac role show platform-admin

# 策略管理
levee rbac policy create --role platform-admin \
  --resource "changes/*" --action "apply" \
  --condition 'env == "prod"'

# 权限检查
levee rbac check --user alice --resource changes/123 --action apply

# 用户角色绑定
levee rbac grant --user alice --role platform-admin
levee rbac revoke --user alice --role platform-admin
```

### F09: ChatOps

飞书/钉钉/Slack 三大企业 IM 平台机器人适配，实现变更协作闭环。

**支持平台**:

| 平台 | 包 | 特性 |
|------|-----|------|
| 飞书 | `feishu.go` | 交互卡片 + 回调签名校验 + 指令路由 |
| 钉钉 | `dingtalk.go` | ActionCard 消息 + 回调加密 |
| Slack | `slack.go` | Block Kit + Slash Commands + Interactive Components |

**核心能力**:
- **变更通知推送**: apply 启动/完成/失败/回滚自动推送卡片消息
- **一键审批/驳回**: 卡片按钮直接触发审批操作，回调鉴权
- **命令路由**: `@levee show <run-id>`、`@levee approve <run-id>`、`@levee rollback <run-id>`
- **交互卡片**: 变更详情卡片、审批卡片、回滚确认卡片

**CLI 命令**:
```bash
# 启动 ChatOps 机器人
levee chatops start --platform feishu --port 9090

# 查看机器人状态
levee chatops status

# 发送测试消息
levee chatops send --platform feishu --user alice --message "test"
```

## Installation

### 从源码构建

```bash
# 克隆仓库
git clone https://github.com/levee/levee.git
cd levee
git checkout v1.3.0

# 构建 CLI
go build -o levee ./cmd/levee

# 构建 Web UI 前端（可选，已预编译嵌入）
cd web && npm install && npm run build && cd ..

# 验证
./levee system version
```

### 快速开始

```bash
# 1. 初始化配置
levee system config set db.path ./levee.db
levee system config set server.grpc.port 9090

# 2. 添加目标机
levee target import --file targets.yaml

# 3. 创建变更
levee new --template deploy-web --params env=staging,version=v2.1.0

# 4. 启动 gRPC 服务端（终端 1）
levee serve --addr :9090

# 5. 启动 Web UI（终端 2）
levee web --addr :8080 --grpc-addr localhost:9090

# 6. 通过浏览器访问 http://localhost:8080
```

## Performance Benchmarks

v1.3.0 包含 9 个包的性能基准测试，覆盖核心路径。完整报告见 `docs/benchmark-report.md`。

### 关键指标摘要

| 包 | 关键 Benchmark | ns/op | 状态 |
|----|---------------|-------|------|
| permission | CheckPermission | ~1,200 | ✅ 良好 |
| permission | CheckBatch (100) | ~8,500 | ⚠️ +18% 回归 |
| dsl | Parser_Parse | ~45,000 | ✅ 提速 -14% |
| dsl | TypeChecker_Check | ~38,000 | ✅ 提速 -24% |
| credential | encrypt | ~344ms | 🔴 +142% (KMS fallback) |
| credential | StoreAndRetrieve | ~292ms | ✅ +1% (端到端持平) |
| channel | Limiter_AcquireRelease | ~379 | ⚠️ +38% (疑似噪声) |
| channel/winrm | WinRMFactory_Create | ~150 | ✅ 提速 -53% |
| batch | Controller_Execute_Serial | ~134μs | 🔴 +64% 回归 |
| audit | HashChain_Append | ~2,400 | ✅ 良好 |

### 性能回归说明

1. **credential 包** (+142%): KMS fallback 路径触发额外 scrypt 调用。生产环境配置 KMS 可用即可避免。
2. **batch 包** (+64%): 控制器初始化引入额外开销，下一迭代优化。
3. **channel 包** (+38%): 疑似单次运行噪声，建议 `-count=3` 复测。

## Security

### 已修复（v1.0.1）

| ID | 严重度 | 问题 | 修复 |
|----|--------|------|------|
| SA-001 | CRITICAL | 凭据明文日志泄露 | 凭据字段全局 redaction |
| SA-002 | CRITICAL | SSH 私钥内存未清零 | SecureZero 调用 |
| SA-003 | CRITICAL | argon2 参数低于 OWASP 建议 | 提升至 194MiB / t=3 |
| SA-004 | HIGH | WinRM 密码环境变量泄露 | 从 env 读取后立即清除 |
| SA-005 | HIGH | Plan hash 未包含审批人 | hash 输入增加 approver |
| SA-006 | HIGH | 回滚未触发独立通知 | 回滚通知路径独立 |
| SA-007 | HIGH | 哈希链校验未校验根哈希 | 增加根哈希锚定 |
| SA-008 | HIGH | 互斥锁抢占未检查状态 | 抢占前状态检查 |

### 安全特性

- 凭据 AES-GCM 加密存储 + argon2id 密钥派生（194MiB / t=3）
- WORM 审计存储 + 哈希链校验，篡改可检出
- 三级审批模型，高危变更强制人工审批
- gRPC TLS + Bearer token 认证
- 插件子进程沙箱隔离，资源限制 + 崩溃恢复
- RBAC + ABAC 多维权限策略

## Known Limitations

1. **单节点部署**: v1.3.0 仍为单节点架构，多节点集群形态（F15）计划在后续版本。
2. **SQLite 存储**: 使用 modernc.org/sqlite 纯 Go 驱动，适合中小规模（< 100 并发变更）。PostgreSQL store 计划在 F15。
3. **插件沙箱 Windows 限制**: Windows 平台不支持 RLIMIT_AS 内存限制，仅超时控制可用。
4. **Web UI 预编译**: 前端构建产物已嵌入二进制，修改前端需重新 `npm run build` + `go build`。
5. **ChatOps 回调**: 需要公网可达的回调地址，建议通过反向代理暴露。
6. **性能回归**: credential 包 KMS fallback 路径和 batch 包控制器初始化有已知回归，详见性能基准报告。
