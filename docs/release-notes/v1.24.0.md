## Behaviour changes (read first)

1. **未分类的插件动作现在按不可逆处理（fail-closed）**。manifest 新增 `reversible_actions`，动作落破坏性 / 可逆 / 未分类三态；只有明确列进"可逆"的才免 `allow_irreversible`。**升级前先看一眼**：`levee plugin test <名>` 会打出 `unclassified (judged irreversible at plan time)` 那一行，`levee plugin info` 会列出两张表；未分类列表非空就意味着这些动词的计划会被 LE082 拒，直到你写白名单或补声明。`serve` 启动也对未分类动作打 warn 并列名。
2. **不可逆判定进 `plan_hash`，且按部署事实取值**。同一个 workflow 在"声明了可逆"与"未分类"的两个部署上会得到不同 plan hash——这是设计预期而不是漂移（审批绑定的是产物，产物本该反映部署事实）。已批准变更若跨这类部署重放，需重 plan。
3. **`depends_on` 现在真的排序**。按依赖书写的 workflow 逐字节不变（稳定排序保持声明顺序），但两类非法图从此在编译期被拒：引用不存在的 step（LE104）、依赖成环（LE071）。存量 workflow 里写错引用名或成环的，升级后 `levee compile` 会开始报错——这是把静默违反声明依赖改成显式失败。
4. **通道会话会被复用**。同一个 `(插件, host, port, type, 凭据指纹)` 的后续 run 复用已拨通的会话，`Close` 只归还租约不杀进程；三道上界（每插件空闲 ≤8 / 空闲 2 分钟回收 / 闲置 30 分钟）兜住资源。期望"每次 run 一条全新连接"的插件需要看这三条上界，而不是假设会话干净。
5. **`run_assignment.result` 有数据库约束了（迁移 v10 会回填一次）**。`'done'`（旧代码把状态名塞进 result 列留下的痕迹）折成 `''`＝"尚无结果"，其余表外值折成 `failed`。升级会执行一次回填，之后绕过 store 的直写会被数据库拒绝。
6. **审批超时的结算变条件写**。同一时刻两个副本清扫只有一边上报；期间已投票的记录不再被 `expired` 盖掉。依赖"重复播报"做去重的下游要注意语义变了。
7. **构建与镜像要求 Node 24**（CI 的 `frontend` / `browser-check` 两处与 `Dockerfile` 的 `NODE_VERSION` / `ALPINE_VERSION` 同步升到 24-alpine / 3.24）。Vite 8 用 rolldown，`manualChunks` **只接受函数式**——手改过 vite.config 的分支要照此改；产物 vendor chunk 1,237,049 → 1,215,229 字节，构建 40s → 5.7s。TypeScript 仍是 `^5.9.3`。
8. **CLI 输出面新增字段**：`plugin info` / `plugin list` 对 `type: module` 记录多两行（`destructive_actions` / `reversible_actions`，其余三类型刻意不输出，避免把"不适用"渲染成"没有破坏性动作"）；`plugin test` 输出三行分类，且**分类核对不过直接报错**。门禁面板的"单步验证"区分 **200 + `passed:false`（判决）** 与 **400（请求被拒）**。

## Security

- **通道池的键用凭据指纹而不是引用名**，指纹改成**每进程随机密钥的 HMAC + 长度前缀**：两行 inventory 写同一个引用名却解析出不同密钥（或跨租户同名）时不会共享同一条会话；指纹也不跨进程可反查。
- **插件破坏型动作默认不再静默通过**（未分类＝不可逆），这是把"没声明"从"安全"里摘出去。
- **`run_assignment.result` 的域约束下沉到数据库**：绕过 store 的直写不再能把非词表值塞进一个下游当判定读的列。
- **依赖收口**（PR #245）：`google.golang.org/grpc v1.85.0`、`aws-sdk-go-v2/config v1.33.12` 与 `service/kms v1.62.1`、`masterzen/winrm` 2026-10-04 伪版本，间接依赖随 `go mod tidy` 更新；web 侧在锁内升级并含 `vue-router 4.6.4 → 5.4.0`。漏洞面本仓只认两条腿——`govulncheck` 与 `trivy`（含真镜像构建），因为 **Dependabot alerts 在本仓被禁用**（API 403），且 `web/` 不在 dependabot 配置里（npm 一动就要重建 `internal/web/dist`，加了只会产红 PR）。
- **`target-ownership.yaml` 的判定链第一次有测试**：坏文件拒绝启动（不静默退回调用方可声明的 labels）、registry 压过 `labels["env"]`、标签冲突是审计而非故障。这条决定 authz 按 prod 还是 dev 判。

## Known gaps after this snapshot

- **`F-1` TypeScript 7 装不上**：TS 7 原生编译器移除了 `./lib/tsc` 子路径，`vue-tsc` 在 `resolveTscPath` 抛 `ERR_PACKAGE_PATH_NOT_EXPORTED`；上游支持在 Vue Language Tools 4.0 线（`@vue/language-core@4.0.0-alpha.2` 的 peer 是 `typescript >=7.1.0-beta`），而 `vue-tsc` 已发布版本停在 3.3.14、无 4.x。复测条件已登记在 `docs/blocked-items.md` 的 F 节。
- **通道"一插件多类型"未做**（D-1c 剩下的那一半）：类型名=插件名，要多种传输就装多个插件。按真实消费方出现再排。
- **五条卡外部凭据/环境**（A 类）：ChatOps 真机 secret、真实 IdP、APNs/FCM、L0 四环境安装演练、租约锁 4–6 周浸泡；**三条等复发取证**（C 类）：`internal/calendar` 的 windows `0xc0000005`、browser-check windows 模式 A（settle 超时）、模式 B（Chrome 没起来）——证据面都已自动留档，判定未改。
- **`POST /gates/verify` 仍不为 `type: probe` 拨号**（`internal/grpc/rest_gate.go` 只在 `cmd` 时 `dialTarget`）：ad-hoc 诊断面经这个端点发起的 remote 探针依旧失败关闭，改它等于让一个 HTTP 端点按需登录目标机，属权限面决定。
- **运营层资产为零**（D-2）：demo 库、角色视频、品牌 GIF 需人手，是面向签单的最大缺口。
- **本窗口新观察（未修）**：`scripts/release_gate.sh` 的 **G-06「测试门禁 10 分钟」只计时、不看退出码**——测试根本没跑起来时它照样报 PASS。本机实测过一次：`GOSUMDB=off` 挡住 1.26.10 工具链切换导致 G-01/02/03/07 全红，同一张报告里 G-06 是 PASS。正确性另有 G-02 与 CI 三条 test 腿兜着，所以不阻塞交付，但这条门禁假阳性比没门禁更糟，应单独一笔改成"跑成且 rc=0 才计时"。
