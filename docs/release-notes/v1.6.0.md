## Highlights

LEVEE v1.6.0 是 **Phase A — 智能运维闭环引擎** 的首个交付版本。本阶段将 LEVEE 从变更流水线引擎向智能运维闭环引擎演进，实现与 OpsMesh 监控平台的对接：接收告警 → 自动诊断根因 → 为后续 AI 修复建议与自动执行闭环奠定基础。

Phase A 聚焦两大能力：

- **告警接入** — 统一告警网关，接收 Prometheus Alertmanager 与自研平台告警，归一化后执行去重 / 聚合 / 抑制
- **基础诊断** — 日志采集 + 日志分析 + 健康探针 + 诊断引擎，告警触发后自动定位根因

完整设计方案见 `docs/opsmesh-integration-design.md`。

## New Features

### 告警网关 (internal/alert/)

统一告警模型 + HTTP 网关 + 多源适配器 + 去重 / 聚合 / 抑制流水线。

**核心组件**:

| 组件 | 文件 | 职责 |
|------|------|------|
| Alert 模型 | `alert.go` | 统一告警结构体（Severity / Status / Labels / Annotations）+ 序列化 |
| Gateway | `gateway.go` | HTTP 网关，接收告警 webhook，路由到适配器，执行流水线 |
| Prometheus 适配器 | `adapter_prometheus.go` | Prometheus Alertmanager webhook 格式解析 |
| 自研适配器 | `adapter_custom.go` | 自研监控平台告警格式解析 |
| Deduper | `deduper.go` | 基于指纹（labels + annotation）的告警去重，TTL 过期清理 |
| Aggregator | `aggregator.go` | 同源同严重度告警聚合，窗口内合并 |
| Silencer | `silencer.go` | 静默规则匹配（label matcher），静默期内告警抑制 |

**流水线顺序**: `接收 → 适配器归一化 → 去重 → 聚合 → 抑制 → 下游处理`

**并发安全**: 所有共享状态结构（Deduper / Aggregator / Silencer / AlertGateway）使用 `sync.RWMutex` 保护。

**CLI 命令**:

```bash
# 启动告警网关
levee alert serve --addr :9092 --downstream http://localhost:9090/alerts

# 列出最近告警
levee alert list --severity critical --limit 20

# 查看告警详情
levee alert show <alert-id>

# 创建静默规则
levee alert silence --match-labels "service=payment" --duration 30m --reason "维护窗口"
```

### 日志采集器 (internal/diagnosis/log_collector.go)

从告警关联目标机自动拉取时间窗口内的日志，支持多源并发采集。

**支持的日志源**:

| 源类型 | 说明 | 采集方式 |
|--------|------|----------|
| `syslog` | Linux syslog | 读取 `/var/log/syslog` 或 `journalctl` |
| `journald` | systemd journal | `journalctl --since --until` |
| `eventlog` | Windows 事件日志 | `wevtutil qe` 查询 |
| `app` | 应用自定义日志 | 用户指定路径 |

**传输抽象**: 通过 `CommandExecutor` 接口抽象远程命令执行，生产环境注入 SSH / WinRM / Agent 执行器，测试注入 mock。

**并发模型**: 多源并发采集，每源独立 goroutine，结果聚合为 `LogBatch`。

---

### 日志分析器 (internal/diagnosis/log_analyzer.go)

对采集的日志进行错误模式匹配、聚类与根因定位。

**8 种内置错误模式**:

| 模式 | 匹配示例 | 置信度 |
|------|----------|--------|
| OOM Kill | `Out of memory: Kill process` | 0.95 |
| Panic | `panic: ...` / `fatal error: ...` | 0.90 |
| Disk Full | `No space left on device` | 0.90 |
| Connection Refused | `Connection refused` | 0.80 |
| Timeout | `timeout` / `context deadline exceeded` | 0.75 |
| Permission Denied | `Permission denied` | 0.85 |
| File Not Found | `No such file or directory` | 0.70 |
| Stack Trace | `goroutine ... [running]:` | 0.60 |

**分析流程**:

1. 逐行匹配 8 种错误模式
2. 按消息前缀相似度聚类（避免同类错误重复计数）
3. 按置信度 × 出现频率排序
4. 输出根因假设（dominant pattern）+ 置信度评分

### 健康探针 (internal/diagnosis/health_probe.go)

对告警关联目标执行四类健康检测，快速排除/确认故障域。

**探针分类**:

| 类别 | 探针 | 检测内容 |
|------|------|----------|
| 网络 | `ping` | ICMP 连通性 + 延迟 |
| 网络 | `dns` | DNS 解析 + 解析延迟 |
| 网络 | `tcp` | TCP 端口连通性 |
| 节点 | `cpu` | CPU 使用率 |
| 节点 | `memory` | 内存使用率 |
| 节点 | `disk` | 磁盘空间使用率 |
| 节点 | `load` | 系统负载（loadavg） |
| 服务 | `process` | 进程存在性检查 |
| 服务 | `port` | 端口监听检查 |
| 服务 | `http` | HTTP 健康端点检查 |
| 数据 | `db` | 数据库连通性 + 简单查询 |
| 数据 | `replication` | 复制延迟检查 |

**跨平台支持**: Linux（/proc 文件系统 + 原生命令）+ Windows（WMI + PowerShell）。

**并发执行**: 所有探针并发执行，单探针超时不影响整体，结果聚合为 `HealthReport`。

### 诊断引擎 (internal/diagnosis/engine.go)

协调日志分析与健康探针，产出综合诊断报告。

**执行流程**:

```
告警触发 → 解析关联目标
         ↓
    ┌────────────┬────────────┐
    ↓            ↓            ↓
 日志采集     健康探针     (预留: 拓扑分析)
    ↓            ↓
 日志分析     健康汇总
    ↓            ↓
    └────────────┴────────────┘
                 ↓
          综合诊断报告
                 ↓
          根因假设 + 置信度
```

**并发模型**: 日志采集分析 + 健康探针并发执行，`sync.WaitGroup` 同步，超时控制。

**多目标支持**: 单次诊断可指定多个目标，各目标独立诊断，结果合并。

**报告生成** (report.go): 结构化诊断报告，包含根因假设、证据列表、置信度、建议动作。

**CLI 命令**:

```bash
# 对单目标执行诊断
levee diagnose host1.example.com

# 对多目标执行诊断
levee diagnose host1,host2,host3 --timeout 60s

# 指定日志时间窗口
levee diagnose host1 --since 30m --log-sources syslog,app

# 指定探针
levee diagnose host1 --probes network,node,service
```

## Roadmap

Phase A 是 LEVEE × OpsMesh 智能运维闭环引擎的第一阶段。后续阶段规划：

| 阶段 | 内容 | 状态 |
|------|------|------|
| **Phase A** | 告警接入 + 基础诊断 | ✅ v1.6.0 已交付 |
| **Phase B** | AI 建议引擎（知识库匹配 + LLM 对话诊断 + 修复方案生成） | 规划中 |
| **Phase C** | 对话引擎（IM 机器人交互 + 自然语言审核 + 全自动模式） | 规划中 |
| **Phase D** | 拓扑分析（SkyWalking/Pinpoint 调用链 + 影响半径） | 规划中 |

完整路线图见 `docs/opsmesh-integration-design.md`。
