# Release Notes — v1.8.0 (Phase C: 自动执行 + OpsMesh 集成)

**发布日期**: 2026-08-18

## 概述

Phase C 为 LEVEE 引入全自动执行闭环与 OpsMesh 平台集成能力，并补齐告警/诊断/对话三大 gRPC 服务接口。至此 LEVEE 完成「告警接入 → 诊断 → AI 建议 → 自动执行 → 结果回传」的端到端智能运维闭环。

## 新特性

### C1: AutoPlanner — 自动任务拆分引擎

- `internal/autoplanner/planner.go`：`AutoPlanner.Plan()` 将 AI 推荐（`Recommendation`）转换为可执行的 LEVEELang workflow，包含风险评估与批次划分
- `internal/autoplanner/risk_assessor.go`：`RiskAssessor.Assess()` 实现风险→审批级别映射
  - 低危（RiskLow）→ LevelStandard
  - 中高危（RiskMedium/High）→ LevelHigh
  - 紧急（RiskCritical）→ LevelEmergency

### C2: AutoExecutor — 全自动执行模式

- `internal/autoplanner/auto_executor.go`：`AutoExecutor` 按风险等级分发审批级别
  - 低危 → 自动执行（LevelStandard）
  - 中高危 → 需人工确认（LevelHigh）
  - 紧急 → 紧急审批（LevelEmergency）
  - 失败自动回滚，回滚也失败则升级告警
- 三种执行模式：`ModeDryRun`（预演）/ `ModeAuto`（自动）/ `ModeForce`（强制）

### C3: PostReport — 事后审计报告

- `internal/autoplanner/post_report.go`：`PostReport` 生成事后审计报告
  - 修复摘要 + 指标对比（`MetricsBefore`/`MetricsAfter`/`MetricsDelta`）+ 审计链验证
  - `ToText()` 纯文本格式输出
  - `ToJSON()` JSON 格式输出，便于机器消费

### C4: OpsMesh Client — 平台集成客户端

- `internal/opsmesh/client.go`：`Client` OpsMesh 平台集成客户端
  - `ReportResult()` — 回传修复结果给 OpsMesh
  - `GetTopology()` — 获取服务拓扑
  - `GetMetrics()` — 获取监控指标
  - `Ping()` — 健康检查
- `internal/opsmesh/types.go`：OpsMesh 交互数据类型定义
- HTTP Bearer 认证 + 重试 + 限速

### C5: gRPC Services — 告警/诊断/对话三大服务

- `internal/grpc/alert_service.go`：`AlertService`
  - `ReceiveAlert` — 接收告警
  - `GetAlertStatus` — 查询告警状态
  - `SubscribeAlerts` — 流式订阅告警
- `internal/grpc/diagnosis_service.go`：`DiagnosisService`
  - `Diagnose` — 触发诊断
  - `GetDiagnosis` — 查询诊断结果
- `internal/grpc/conversation_service.go`：`ConversationService`
  - `SendMessage` — 发送对话消息
  - `SubscribeConversation` — 流式订阅对话
- `internal/grpc/pb/levee_extra.pb.go` + `levee_extra_grpc.pb.go`：手动编写 pb 代码（protoc 不可用环境下的兼容方案）

## 变更

- `proto/levee.proto`：追加 `AlertService` / `DiagnosisService` / `ConversationService` 服务与消息定义
- `internal/grpc/pb/`：新增 `levee_extra.pb.go` + `levee_extra_grpc.pb.go`（手动编写）
