# v1.18.0 Release Notes

**Release Date**: 2026-10-03

## Overview

Everything a customer deployment needs is now in the repository: a Helm
chart for Kubernetes sites (single-node and cluster shapes), an idempotent
bare-metal installer with a hardened systemd unit, a multi-arch container
image published to GHCR on every tag, a cross-region scenario playbook with
a CI-guarded example workflow, and a deployment manual that grew a delivery
checklist. The docs-vs-code consistency pass also closed three stale
statements. Per-item detail in [CHANGELOG.md](../../CHANGELOG.md).

## Kubernetes: Helm Chart (`deploy/helm/levee`)

- `mode=single` (SQLite + PVC) and `mode=cluster` (1 master + N workers on
  a shared PostgreSQL; node identity/address via the Downward API; workers
  can point their snapshot directory at a shared RWX claim).
- Credentials, master password and the PG DSN all live in Secrets
  (`auth.existingSecret` takes the whole thing over).
- Probes: readiness `/healthz` (503 until services are registered),
  liveness TCP (a misconfigured instance should not restart-loop).
- A bundled single-replica PostgreSQL for demos only — plainly labelled;
  production points at the customer's own PG/RDS.
- Boundaries stated in the template comments: the Service targets the
  master replica only (the `WatchChange` event bus is in-process, so
  fronting multiple replicas drops events for subscribers), and the GHCR
  image starts private (imagePullSecrets or sync to the site's registry).
- Verified by `helm lint` plus full renders of both shapes (12 documents
  cluster / 6 single), every document YAML-parsed.

## Bare Metal: One-Command Install

- `deploy/baremetal/install.sh` — idempotent (tested twice in a container):
  creates the system user, installs the binary, renders the unit's paths
  from `--prefix/--data-dir`, writes a 0600 credential template and never
  overwrites existing files.
- `deploy/systemd/levee.service` — least-privilege hardening
  (`ProtectSystem=strict`, `ProtectHome`, `ReadWritePaths` limited to the
  data dir) and `$LEVEE_SERVE_EXTRA` expansion for cluster flags (unset
  expands to nothing, no failure).

## Container Image on Every Tag

The release workflow gained a dedicated `image` job: buildx (QEMU)
multi-arch linux/amd64+arm64 images pushed to
`ghcr.io/levango7/levee:<version>` and `:latest`. It is deliberately
**decoupled from goreleaser** — a registry outage or buildx failure turns
the run red without blocking the binary/archive release. All actions are
pinned by commit SHA.

## Cross-Region Scenario Playbook

`docs/scenario-cross-region-ops.md` targets the mid-to-large-group shape
(one core datacenter + 4–5 regional DCs): pain-point → shipped-capability
mapping, reference topology, a pilot acceptance table, positioning (sell
the governance layer around existing sync tooling, not another sync
product), and honest boundaries. Its companion
`examples/workflows/dr-switch-orders-db.yaml` (per-target serial batches,
regional-timezone window, high approval, `confirm=yes` gate, post-switch
verification) compiles clean and is now guarded by
`TestShippedExamplesCompile` forever.

## Deployment Manual

`docs/deployment.md` §14 documents the Helm path; §15 is a delivery
checklist (named tokens/OIDC, gRPC kept off public networks, master
password via secret, `levee doctor` green, pilot drills, backup/restore
drill, upgrade path, audit-chain verification) — its first four items bind
the production-admission constraints from `docs/security-audit.md`.

## Consistency Fixes (docs vs code)

- `leveelang-spec.md`: the `allow_irreversible` field is now marked as a
  spec target **not yet wired** (no parser field, LE082 has zero
  producers); today's irreversible protection is the two real layers —
  `mysql.replica_switch`'s runtime `confirm=yes` gate and the plan-side
  high-approval routing. Wiring it (a compile-time gate that changes
  existing behaviour) is registered as a roadmap P1.
- `security-audit.md`: two historical boundary notes annotated as closed —
  the trace chain is wired (v1.14.0) and the PG plpgsql triggers have a
  real CI regression run; the risk-rating line carries a dated update.

## Upgrade Notes

- No behaviour changes to existing binaries or APIs in this release; the
  new content is delivery tooling and documentation. The GHCR image and
  Helm chart are new artifacts at this version.
