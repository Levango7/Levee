# v1.16.0 Release Notes

**Release Date**: 2026-10-03

## Overview

The last three packages that were "library-ready but product-unreachable" are
disposed of, taking the unlinked-package count to **zero**. Every `internal`
package is now reachable from the `levee` binary through a config face, a CLI
command, or a documented retirement. Per-item detail in
[CHANGELOG.md](../../CHANGELOG.md).

## APM Topology Analysis, Wired Into Diagnosis

`internal/diagnosis/topology` (SkyWalking / Pinpoint collectors) now feeds the
diagnosis pipeline's **impact-radius stage** — flow step 3d of the OpsMesh
integration design. When `diagnosis.topology.*` is configured (default OFF),
the engine collects the service graph for its look-back window as a third
parallel evidence source, analyses the pivot service's position with the new
`ImpactRadius` (upstream callers, downstream callees, unhealthy edges at a
10% default error-rate threshold, ≥50% graded critical), and emits `service`
-category findings that participate in the standard severity ordering.

Honest boundaries: a target absent from the graph is a silent skip (not every
host is an APM-instrumented service); a collect failure is recorded on
`report.Errors` without failing the diagnosis; an unknown provider or a
provider without an endpoint degrades with a warning rather than blocking
startup.

## Ansible Import Is Now a CLI Command

`levee import ansible <playbook> [--out workflow.yaml] [--name name]`
translates an Ansible playbook into a **compilable** LEVEELang workflow:

- translation only — nothing executes, no change is created;
- the play's `name:` maps into the workflow name (otherwise the output fails
  the parser's LE002 — an importer must not produce what its own compiler
  refuses), with the file base name as the fallback;
- the new `dsl.MarshalWorkflow` renders the AST back to LEVEELang YAML and is
  **fail-closed**: any non-empty field it cannot express faithfully
  (inputs, approvals, gates, rollback, snapshots) returns an error naming the
  field — never a silent drop; args are emitted in sorted-key order so output
  is byte-stable for version control;
- the emitted bytes must pass the **same parser + validator doors as
  `levee compile` strict mode** before anything is written, so a translation
  can never produce uncompilable YAML. The import → emit → re-parse →
  validate round trip is pinned by test.

## OpsMesh Result Reporting, Wired

With `opsmesh.*` enabled, the outcome of **alert-driven** fixes (runs whose
params carry an `alert_id`, stamped by the conversation bridge when a session
started from an alert) is POSTed to
`/api/v1/alerts/{id}/resolution` — alert_id, success, workflow_id, step
counts and rollback usage. Runs without an alert id are not reported (there
is no platform alert to resolve, and inventing one would corrupt the
platform's records); a report failure is logged, never fatal.

One identifier misuse was corrected along the way: the effect-learning
producer had been stuffing the *recommendation* id into
`FixOutcome.AlertID`; it now reads the real `alert_id` param. The topology /
metrics **pull** direction awaits OpsMesh-side addressing semantics (the
platform API takes a service name while diagnoses carry host targets) —
documented in the config comments and README rather than guessed at.

## Upgrade Notes

- `diagnosis.topology` and `opsmesh` are new optional sections; absent =
  no behaviour change.
- `levee import ansible` writes to stdout by default; `--out` writes a file.
  The emitted workflow still has to go through `levee plan` → approve →
  apply like any hand-written one — the importer creates no shortcuts.
