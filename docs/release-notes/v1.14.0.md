# v1.14.0 Release Notes

**Release Date**: 2026-10-03

## Overview

This release closes out everything accumulated since v1.13.0 (15 PRs): the
governance loop is now end-to-end real (approvals bind identity, the change
window enforces, multi-tenancy is wired from verified credentials, and BOTH
audit tables carry tamper-evident chains that the production path actually
seals), the CI pipeline gained the security and freshness gates it was
missing, and the "built but unreachable" surface was either wired behind a
config face or retired on the record. No known defects remain open; the
per-item detail lives in [CHANGELOG.md](../../CHANGELOG.md).

## Governance Loop Closures

- **Approval identity + quota + window enforcement**: approval votes bind
  the authenticated subject (concurrent-vote revision CAS, settlement CAS),
  quotas are decided by level, and client `auto_approve` can no longer
  bypass the approval chain for high/emergency changes. The `window` block
  — promised by the spec but never read by any code — now blocks
  out-of-window plans at the single plan funnel (LE020/LE021), with
  cross-midnight windows supported and fail-closed on undecidable
  declarations.
- **Authorization as one composite decision**: the permission matrix and
  the role tree combine into a single `authz` judgement (environment
  reachability × in-environment action capability), wired into the
  change-scoped governance RPCs with a diagnostic command.
- **Multi-tenancy wired from verified credentials**: the tenant is a
  property of the CALL (resolved from signed tokens / OIDC claims / SSO
  session), never of a client header; `TenantStore` is a true drop-in
  `state.Store`. Disabled by default — and that default is load-bearing:
  enabled, a credential without a tenant is refused, never defaulted.
- **Rollback verified for real**: post-rollback verification is graded
  (`VerifyAndGrade`), no longer cancelled by the caller
  (`context.WithoutCancel` + a 2-minute bound), the notify transport is
  wired (recipients resolved from `runs.creator`), and the manual rollback
  path restores the run-level snapshot baseline — so LE102 was withdrawn.
- **Audit chains that are actually sealed**: the `audit` table joined the
  tamper-evident set (WORM triggers + a GLOBAL hash chain, sealed
  idempotently on every write), and the per-run **trace** chain is now
  sealed by the production path at every terminal settle point (apply
  success, engine error, cancel, retry closure, takeover) — until this
  release no trace chain was ever built outside tests.

## CI Security & Freshness Gates

- **Supply-chain hardening**: every action pinned to a commit SHA, top-level
  least privilege, per-job timeouts.
- **govulncheck gate**: symbol-level vulnerability scan wired as a required
  check; the go directive bumped to 1.26.6 so the scanned toolchain matches
  the shipped one (25 stdlib findings cleared; the x/crypto openpgp advisory
  is a Module-level note with no fix, recorded on purpose).
- **gosec as a pinned runner program**: the docker action's bundled
  toolchain (GOTOOLCHAIN=local) cannot survive a go.mod bump — the scanner
  version stays pinned while the toolchain floats, exactly like
  govulncheck.
- **Trivy, CodeQL, gosec, vet, lint, frontend, integration/e2e/postgres
  (-race)** all wired into one aggregate `check (all jobs passed)` gate.
- **Benchmark smoke**: all 121 benchmarks execute once in CI — a rotting
  benchmark now fails the build instead of rotting silently.
- **Web dist freshness gate**: CI requires the committed `internal/web/dist`
  (embedded into the Go binary) to be byte-identical to a fresh build of the
  exact source; the previously stale assets (19 of 33 drifted) were
  refreshed, and `*.svg` is pinned to LF so Windows `make web` matches CI.

## Fixes

- **REST gateway dual-URL-shape routing**: the frontend's
  `/api/v1`-prefixed resource paths no longer all return 400 — one router
  resolves both URL shapes through shared handler tables, the public-path
  list works under both shapes (SSO login bootstrap unblocked), and the
  guard tests read the frontend's real call sites instead of re-copying the
  routing rules.
- **PG-side audit WORM regression net**: the plpgsql triggers are now
  exercised against a real PostgreSQL in CI (seven content columns + DELETE
  refused, chain columns writable, seal restores) — previously only trace
  had PG coverage.
- **PG backup restore**: consistent snapshot dumps (single
  `REPEATABLE READ` transaction + advisory lock), FK-topological replay,
  fresh-schema restore as the main path with destructive restore as
  explicit opt-in.
- **Dispatch orphan reclaim**: a worker dying before claiming is recovered
  by claim timeout + epoch fencing; pending assignments count toward
  capacity.

## AI Assist & Package Disposition

- **`ai.llm` config face**: the recommend engine's hybrid LLM mode is now
  operable from config (`ai.llm.enabled/provider/api_key/model/...`) in both
  `serve` and `levee converse`. Default OFF and that default is load-bearing:
  no client is constructed, the engine runs the pure knowledge-base path
  byte-identically to before; construction errors degrade with a loud
  warning.
- **Retired on the record**: `internal/recommend/rag` (FNV-1a pseudo-vector
  embedding — wiring it would degrade retrieval into noise) and
  `internal/scheduler` (agent dispatch duplicating the wired
  `internal/dispatch`). `internal/compat`'s ungated simulated executor was
  weeded (the import layer and the D-08 mapping decision remain). Unlinked
  packages: 8 → 6, all documented in the README capability table.
- **Observer slots fan out**: the Jira mirror no longer gets silently
  displaced by a second mirror — `WithDecisionObserver` /
  `WithApprovalCreateObserver` keep every install, clear on nil, and
  panic-recover per call.

## Documentation

  per item), 10 still valid (all P2) with 4 fixed on the spot (`--json`,

## Upgrade Notes

- The `window` block is now enforced at plan time: a workflow declaring a
  window whose plan moment falls outside it is refused (spec-promised
  behaviour, not a regression). Re-plan inside the window or adjust it.
- `verify_after` remains opt-in; declaring it now actually runs the
  post-rollback verification.
- Master requires the aggregate CI check; the CI toolchain follows
  `go 1.26.6` (bump local toolchains accordingly).
- The stale duplicate `main` branch was deleted; the default branch is
  `master`.
