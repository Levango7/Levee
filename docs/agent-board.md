# 多 agent 协作留言板

这份文档说明留言板（`internal/agentboard` 负责解析与校验）的格式与用法。

## 它是什么，不是什么

**是**：一个目录，里面每个文件是一条**事实通告**——"某个 agent 正在某条分支上动某些文件，这条声明在某时刻之前有效"。

**不是**：命令通道。条目里没有优先级、没有派活、没有请求。合并与推送的决定权始终属于仓库的人；留言板也不改变取证规则——**别的 agent 说它验过了，不等于你不用自己重跑**。

留言板存在的理由是本仓真实发生过的四类碰撞：一个会话建的工作树被另一个会话清理；两次把活干在错的 checkout 里；浏览器级检查连到了别人 checkout 的 dev server（默认端口 5173/4599 在本机就是别人的）；两条 PR 同时改同一个高热文件却互相不知情。这些都不是代码缺陷，是**缺一条事实**。

## 板子放在共享文件系统，不放在仓库里

目录由 `-dir` 旗标或环境变量 `LEVEE_AGENT_BOARD_DIR` 给出，**刻意没有默认路径**——凭空造一个默认值，会让每个 agent 读不同目录却以为自己协调过了。

不放进 git 有两条理由：

1. 提交在分支上的声明，别的 agent 要先 fetch 再 checkout 才读得到，而那时候碰撞已经发生了；
2. 合进 master 的声明会开始过期，之后每一个无关的构建都因为一条没人认领的过期条目变红。

所以：**留言板是本机（或本环境）的共享状态，仓库只负责携带它的格式定义与校验器**。

## 一个 agent 一个文件

文件名必须匹配 `^[a-z0-9][a-z0-9._-]{0,80}\.md$`（小写、不含斜杠），例如 `qoder-a5c.md`、`opencode-7.md`。

用多个文件而不是"一块大家往末尾追加的公告板"，是因为后者在每条并发分支上都会撞 git：协调工具本身不该成为冲突来源。`README.md` 允许存在于板目录，它是格式说明、不算条目。

## 键

| 键 | 必填 | 语义 |
| --- | --- | --- |
| `agent` | 是 | 谁写的。与文件名一起构成"这条话的来源"。 |
| `branch` | 是 | 正在动哪条分支。同一条分支被两个文件声明 = 判红（到底哪份是准的无法回答）。 |
| `state` | 是 | `active` 或 `done`，只有这两个值。 |
| `updated` | 是 | RFC3339 带时区偏移，例如 `2026-10-15T03:04:05+08:00`。写进未来 = 判红（那是在谎报新鲜度）。 |
| `ttl-minutes` | 是 | 有效时长，整数，5-1440。到期后 `active` 就是**失效声明**，`done` 就是**噪音**，两者都判红。 |
| `worktree` | 否 | 工作目录绝对路径。碰撞里最贵的一类（工作树被并行清理）靠它才知道该不该收手。 |
| `owns` | 否 | 逗号分隔的相对路径清单，表示"我正在动这些文件"。用正斜杠。 |
| `notes` | 否 | 一句话事实。不要写成指令。 |

键表是**封闭词表**：未知键按错误处理，而不是忽略。理由很具体——把 `ttl-minutes` 打成 `ttl_minutes`，如果被忽略，这条条目就永远不会过期，读的人会把它当成有效声明。

## 用法

```bash
go run ./internal/agentboard -dir "$LEVEE_AGENT_BOARD_DIR"
go run ./internal/agentboard -dir /tmp/scratch-board -now 2026-10-15T12:00:00Z
```

输出三段：能读的条目、**重叠声明**（提示，不是拒绝）、`owns` 汇总出来的"现在有人正在动的文件"。退出码：`0` 板子诚实、`1` 有条目在说谎（畸形/过期/同分支重复）、`2` 没给板子路径（区分这两种是必要的：把"配置缺失"报成"条目过期"会引向错误的处置）。

> **`go run` 会把退出码压平**：`go run ./internal/agentboard` 遇到非 0/1 的退出码时自己以 1 结束，
> 只在 stderr 打一行 `exit status 2`。上面三种码是**编译出来的二进制**的实测行为
> （`go build -o agentboard ./internal/agentboard` 后 0/1/2 各验过一次）。要按退出码分支的调用方
> 请用二进制；直接读 stderr 那行 `exit status N` 也能拿到真码。

## 冲突怎么读

两条 `active` 且未过期的条目声明了同一路径 → **报出来，不拦**。两条分支改同一个文件在评审队列里是正常状态（例如 #160 与 #161 都改 `internal/grpc/rest.go`）；把这种事变成硬失败，结果只会是大家绕过留言板。真正需要不可能的是"板子对什么是活的说了假话"，需要被看见的是"这个文件别人也在动"。

## 谁可以删过期条目

任何人。过期条目按定义已经不再断言任何东西，删掉它不是否决别人的工作，而是清理一条失效声明。删除时不需要征得原作者同意，但如果那条工作还在进行，正确做法是**由原作者续期**（更新 `updated`）而不是让别人删。
